# 隐私请求受理

会员路径：会员账号 / 设置与隐私 → 隐私与数据权利。请求提交后只显示“已受理”；后台具体回复显示在同一记录下。不得用“已回复”冒充已删除、已注销或已导出。

历史运维标识 `cisme-privacy-operations` 的 `support` 角色不等于已认证的管理身份。API 管理入口只接受服务端验证过的签名 operator 会话，旧共享 Token 与自报 Principal 不能选择审计主体。CLI 仅限已获授权的本地/运维环境；它直接连接数据库，调用前必须通过环境访问控制核验操作者，不可作为公开 API 凭据替代品。`support` 不能执行复核负责人动作。

## 读取和回复

管理台“隐私与数据权利受理”区需要已登录的 operator 会话。也可在获授权的运维环境使用 CLI，DATABASE_URL 由部署环境注入，勿将凭据复制到报告或命令记录：

```sh
npx tsx scripts/privacy-requests.ts list cisme-privacy-operations
npx tsx scripts/privacy-requests.ts respond cisme-privacy-operations REQUEST_UUID response.json
```

`response.json` 还须包含读取时的 `expectedVersion`，例如 `{"status":"reviewing","response":"本次具体核验要求或实际处理进度","expectedVersion":1}`。状态只接受 reviewing/responded；回复最长 4000 字。回复是对真实会员的通信，应由获授权受理人员核实后提交，不发送演示回复。

## 实际处理

1. 核对当前会员、请求范围、所涉记录、权属及必要性。不能要求无关身份证材料，也不能将别人的记录交给请求者。
2. 查阅/复制请求：整理该会员相关信息，在安全渠道核验交付对象后提供；避免在公共链接或普通日志中输出。当前自动路径仅在本地 `APP_ENV=test`、专用密钥、`dev_test` 合成身份、两名不同 `review_lead` 复核后生成会员资料子集；它在本人会话下限时查看、可撤销，始终标记部分完成，不能冒充自动全量导出。
3. 更正/删除/注销/撤回：先说明影响、仍需保留的具体记录及依据；调用对应已支持的业务操作。涉及关联账本、审计、对象存储或外部处理商时，逐项记录实际执行结果。不可直接级联删除账本，也不可仅改工单状态便告知完成。
4. 对暂不能删除的依法保留或技术限制部分，解释理由、限制用途及后续措施。备份恢复必须重新应用已执行的删除/撤回记录。
5. 回复中列明已完成、未完成与下一步。每天检查未处理队列；运营团队负责实际核验和执行，不依赖会员反复催办。

数据库有每会员每天 10 个不同请求的限制，相同尚未回复的请求自动去重。只有 support/review_lead 可读取队列和回复；所有回复记录操作审计。当前无真实会员工单，未以伪造生产请求进行验收。
