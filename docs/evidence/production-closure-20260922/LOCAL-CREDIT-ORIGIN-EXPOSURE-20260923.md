# 原权益来源冲正后的本地退款冻结（2026-09-23）

复核发现：零现金售后会把 1 分等原权益退回原批次；如果该批次来源订单此前已按签名渠道退款冲正，来源权益可能仍有未覆盖风险，刚退回的金额会重新变成可用余额。原签名退款收件器在退回权益后会重算来源冻结，本地零现金路径此前缺少这一步。

已在现有退款审批事务中按来源订单顺序加锁，退回原批次后复用现有风险冻结函数，连同成功事实、不可变账本和审计一起提交或回滚。审计保留每个来源订单的目标冻结、新增冻结与未覆盖金额；不发起零元微信退款。普通无来源风险的退回仍不新增冻结。

隔离 HTTP 集成使用已核验支付订单和受控签名渠道替身：先支付两件 1 分商品，其中 1 分来自另一已赚取的权益批次；来源订单随后完成签名退款及佣金冲正；再分别退款两件，第二件走本地零现金路径。断言退回的 1 分在同一事实中生成 `-1` 冻结，不能重新成为可花权益。定向 `payment-http-simulation.test.ts` 51 项通过，类型检查通过。没有触及真实资金或正式订单。
