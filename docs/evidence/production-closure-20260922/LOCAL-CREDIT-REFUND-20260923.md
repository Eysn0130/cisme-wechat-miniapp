# 本单零现金商品的原权益退回（2026-09-23）

本批在原售后、退款申请、退款意图、来源批次及审计表内增加 `local_credit` 执行类别。已核验支付的混合支付订单若本次**选定商品数量**仅由原购物权益支付，售后申请仍可入案；另一名有退款审批权限的管理员批准后，在同一数据库事务内核对原支付、累计订单/批次预算、当前数量与退款构成，登记终态意图并把权益退回原批次。该路径不创建微信 0 元退款，不生成伪造的渠道成功回执；现金退款仍必须等微信可信成功事实。

隔离 PostgreSQL / 受控微信协议替身中的完整回归：两件、订单现金 1 分加原权益 1999 分；先退第一件（现金 1 分、权益 999 分），等待模拟签名微信退款成功；再退剩余一件（现金 0 分、权益 1000 分），本地同步成功。验算本地意图不进入渠道任务、不能对本地意图发微信查单、再次退回 1 分被账本守卫拒绝、剩余商品数量为 0。测试不代表真实扣款、真实退款或生产数据迁移。

数据库迁移 `202609230012_local_credit_refund.sql` 只扩展旧数据兼容约束，旧微信退款默认为 `wechat`。本地成功必须先有已经批准的原退款申请，原权益分配合计必须等于申请总额，原权益入账还受来源批次、订单归属和累计可退额约束。存在本地权益退款数据后，回滚该迁移要求先制定数据保全方案。原生页面按实际执行类型将仅退权益成功展示为“购物权益已退回”；本批原生包仍须以当前哈希独立验收。

正式服务器尚未运行这次迁移；`main` 与 production 也尚未更新。正式隐私执行、真实备份恢复、原生和设备验收仍分别核对，不能用本次隔离测试替代。
