# 用户管理复核、直接联系资料与加载优化

对应 PRD UM-01–UM-09，保持原生页面结构与原有会员资产来源。Owner 于本轮明确要求管理员直接查看联系资料、使用文字复制按钮；此要求替代旧的用途确认弹层交互。

## 最终行为

- “日志”以该会员本人作为操作者读取关键业务事实，包含护理保存命令，排除 HEHEHE 等管理员针对该会员的后台操作；管理员审计独立保留。
- HEHEHE 的最高管理员绑定由服务器核验 canonical 微信 UUID；仅该账号出现“新增管理员/管理权限”。从现有会员选择并按职责保存，具备版本、幂等、依赖校验及授权/撤销历史；不创建假会员，最高管理员身份和基础管理权限固定，其余业务职责可调整，不自动为普通会员授予权限。

- 有 member.contact.read 的管理员进入会员详情即看到手机号；地址分类按该会员批量解密展示。服务端自动记录固定业务用途与审计，不再填写用途或二次确认。手机号、地址及已填写微信号提供“复制”，复制前重新核验服务端权限与 owner 绑定。
- 联系资料仅驻留当前可见会员详情；关闭、离页、身份/环境变化或失权清空。复制请求迟到时不得修改新详情，也不得写入剪贴板。导出仍不包含联系方式、地址、健康资料或收款信息。
- 活动发券使用服务端 issueRewards 操作许可，保留原商品与会员管理职责；履约权限不等于发券。过期推荐关系不显示为当前归属，永久有效归属保留；券锁定显示“订单占用”。
- 同一排序与筛选下，五种表格视图复用已读数据，分页游标不受显示维度影响。刷新和同身份返回保留已显示的非联系资料，立即后台核权；401/403 清空。首次载入使用静态稳定占位，移除可见“加载中”文本与骨架闪动。
- 会员数量查询只读取身份和筛选关系，不重复读取头像、积分或财务汇总。管理中心已有 Wi-Fi 代码包预加载；用户管理页补齐常用订单、客服、券、积分、分享官与隐私业务代码预加载，不提前读取联系资料或健康问卷。

## 验证范围

真实体验数据库以只读一致性快照逐会员核对昵称、私有头像、会员卡号、积分账本/批次、券、已核验支付/退款与分享官来源。公开存档只包含数量和核对结果，不包含真实昵称、头像、联系方式、订单号或会员UUID。没有伪造授权会话。

基线时有4位真实微信会员，其中2位已保存有效头像，另2位尚未保存；未发现错配。真实库尚无活动券、正装券或分享官事实，正向状态以独立合成业务回归验证，不声称真实发券或真实结算实测。

新增回归覆盖直接联系资料、复制中断与失权、发券职责分离、优惠券占用、过期与永久归属、视图复用和分页，以及既有签名支付/退款、获奖券领取、正装券、推广订单与月结在详情中的映射。合成用例保留不可变历史，随其专属数据库一起清理，不删除或关闭业务历史保护。

原生微信开发者工具证据绑定最终小程序源码哈希；使用隔离合成数据及受控迟到/慢响应。没有可连接手机，真机待验；全产品47路由完整设备/字号/网络矩阵仍为 blocked。

服务端为应用更新：117条历史迁移保持字节一致，不执行迁移或会员数据修补。`operations-source/` 保留部署步骤；停写后加密快照并核对194张表原列、原行指纹，候选进程开放写入前使用 PostgreSQL 事务只读选项，避免带审计的 GET 写入。正式库保持不变。测试、CI、原生验证、部署和上传以独立回执为准。
