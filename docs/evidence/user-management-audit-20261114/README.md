# 用户管理复核与最小修复

对应 PRD UM-01–UM-08，保持 0.1.48 的页面结构与业务来源。

## 修复

- 联系方式每次弹层独立绑定响应；关闭、切换地址、重新打开或刷新后，旧结果及旧请求完成回调不能影响新弹层。
- 用户管理权限撤销后，会员、联系方式、档案、分享官财务展示行等派生数据一起清空。
- 活动发券入口使用服务端独立 `issueRewards` 操作许可，继续要求原有商品与会员管理职责；履约权限本身不能开启发券入口。未新增或授予管理权限。
- 已过期的历史推荐关系不显示为当前推荐人；永久且有效的客户归属保留。
- 正装券被订单锁定时显示“订单占用”，不显示内部英文状态。

## 验证范围

真实体验数据库以只读、一致性快照逐会员核对昵称、私有头像、会员卡号、积分账本/批次、券、已核验支付/退款与分享官来源。公开存档只包含数量和核对结果，不包含真实昵称、头像、联系方式、订单号或会员UUID。没有伪造授权会话或读取联系资料明文。

原始基线时有4位微信会员，2位已保存有效头像，另2位尚未保存；未发现错配。真实库尚无活动券、正装券或分享官事实，相关正向流程须使用独立合成用例验证，不声称真实发券或真实佣金结算实测。

新增回归覆盖迟到联系方式响应、重新打开时的忙碌状态、失权清空、发券职责分离、优惠券订单占用、过期与永久归属，以及既有签名支付/退款、获奖券领取、正装券、推广订单和月结数据在用户详情中的映射。

原生微信开发者工具按当前小程序源码哈希重新采集截图和交互证据，数据为隔离合成数据。没有可连接手机，真机待验；全产品47路由完整设备/字号/网络矩阵仍为 blocked。

本轮服务端为应用代码更新：历史117条迁移全部保持字节一致，不执行迁移或会员数据修补。`operations-source/` 保留经审阅的部署步骤；停写后加密快照并核对194张表原列和原行指纹；候选进程开放写入前额外使用 PostgreSQL 事务只读选项，避免带审计的 GET 写入，正式环境保持不变。测试、CI、上传及部署结果以同目录独立回执为准。
