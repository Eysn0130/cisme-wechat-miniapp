# 底部导航返回时的卡片稳定性修复

源码包：`e627214bfdff6520d9febd04ad984e61849425e810511eae21d9da62881fbc29`。修改前包为 `7fd3e10ec169581684ff01f5161e82c62fd065f74d3b16560dcb894ce2d8a6f2`；逐文件校验见 `source-proof.json`。

问题来自页面在每次 `onShow` 重新请求时，将已经展示过的内容切回初次加载：提示行插入文档流，活动卡片被清空，日常护理文案先被加载或无周期占位覆盖，个人页的资格入口也会先移除再恢复。

本轮只调整四个底部导航页面的加载展示，复用既有请求、组件、样式及账号归属机制。已展示的同一账号、同一环境资料在刷新期间留在原位；新结果返回后原位更新。首页及个人页的日常护理文案与核心资料一起投影，避免中间出现无周期占位。社区仍重新读取能力，创作入口及审核权限沿用原来的核验。没有新增持久缓存或接口、数据库、依赖变更。

交互约定：首次进入和归属变化保留真实加载状态；首页游客继续看到授权入口。返回刷新仍发起实际请求并维持提交、活动操作和管理权限的原有守卫，保留的展示不构成授权。请求失败展示可重试的真实错误，资格核验失败清除对应入口。切换身份或环境清除旧快照，隐藏页面的迟到响应不能覆盖当前页面。已确认的空护理记录卡片在刷新中继续保留。没有新增动效、尺寸或排版 token，继续使用原生按钮的禁用语义及现有错误提示。

需求对应：PRD V2.1-R4 附录 L `CARE-DAILY-03`、`AUTH-RESTORE-03`；附录 M `PROFILE-SYNC-01`、`PROFILE-CARE-01`、`CARE-DAY-CALENDAR-03`。更新后的当前源码清单继续保持全量验收 `blocked`；修改前清单原样归档到 `../visual/source-acceptance-7fd3e10ec169.json`，历史截图未改标。
