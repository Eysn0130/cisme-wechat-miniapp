# 社区创作底部双操作修复

用户从“＋”经相册、相机或写文字进入最终创作页时，只能看到“存草稿”。源码原因是公开发布能力为false时，右侧发布按钮被wx:if移除，左侧同时改为填满底部的主按钮。2026-11-03匿名读取体验接口仍为publicEnabled=false、draftsEnabled=true；这与普通帖子的人工审核是否存在是不同事实。

本轮只修改最终创作页WXML／WXSS，沿用现有1:2按钮比例、48px触达区、紫色及边框令牌。左侧“存草稿”继续私人保存，右侧改为“去发布”，始终保留两个按钮节点。原因提示和重试放在固定按钮行上方，并使用恒定状态容器，能力刷新不重建按钮，也不因提示行数变化上下推动按钮。上传、排序、未知写入、图片修改恢复、键盘及只读稿状态的保护保留；能力关闭或未知时，发布按钮明确禁用，并提供原因／重新检查，不能冒称已发布或把不可用功能装成可用。

直接发布沿用现有真实保存及submit接口，不增加发布设置层、不恢复人工审批。当前自动内容安全、身份、版本及服务端公开能力校验保留。两个交互约定及状态／无障碍／验证合并记录：保存不产生公开意愿，失败保留本人输入；去发布在真实能力启用时保存当前版本并提交直接发布，重复动作受互斥保护；辅助文字解释禁用，读屏区分私人保存与公开发布，状态变化可被宣读，未知能力可重试，安全区及键盘避让沿用原生方案。对应PRD COMPOSE-ACTIONS-01至04、COMM-DIRECT-PUBLISH-01至06。

实际通过CUA查看本机rednote的“＋”入口（相册、相机、文字）和空白文字编辑器的Next分步动作，随后退出。未输入或上传参考内容，未保存草稿或发布。本轮没有查看其最终发布页；既有PRD K.10已记录历史实际发布页参考，保留原始来源，不冒充本轮新观察。用户明确要求的最终双按钮标签作为本次交互目标，保持CISME的原生视觉及现有保存／发布路径。

新增14项真实WXML渲染用例，覆盖可编辑状态的双按钮、公开能力切换节点连续性、关闭原因、未知能力重试、写入互斥提示及键盘／只读边界；修复前其中6项失败。原有相册／图片编辑、文字卡片、本人草稿、发布及迟到响应测试保留。全量3073项单元测试通过，1项既有跳过；两端类型检查通过。官方WXML／WXSS局部编译摘要及不存在文件的负面对照仅记录各自结果，不能等同于整页或真机验收。
