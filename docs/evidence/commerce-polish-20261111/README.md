# 购买流程、积分选择与文字操作精修 · 2026-11-11

本轮依据用户对结算、订单详情、边框文字按钮的逐项批注，以及“全面精简、最小修正、准备正式提审”的委托。保留原生微信小程序和已有品牌视觉；不增加页面、依赖或支付通道。

## 设计和实现依据

优先级遵循 AGENTS：PRD R4 / 真实状态 → 微信原生 → mobile-ui-ux-designer → taste-skill 视觉辅助。本轮使用 Impeccable clarify / polish 和已安装 design-taste-frontend；核对了用户指定的两个上游仓库：[Impeccable](https://github.com/pbakaus/impeccable)、[taste-skill](https://github.com/Leonxlnx/taste-skill)。这是操作型界面：用户在付款前看清商品、地址、金额和积分选择，付款后看清发货状态与售后入口。

原始截图：`docs/design/buyer-payment-flow-20261111/`，0.1.38 / 0417ae2f3e0d…；`refined/` 与 `source-*-interim/` 为迭代过程，均不替代最终证据。最终截图和 SHA 清单见 `final/manifest.json`。网页仅排列真实原生截图供审阅，不替代小程序验收。

## 信息层级与交互合同

1. 商品详情选择规格与数量 → 确认订单选择地址、核对金额 → 提交订单 → 订单详情主动微信支付 → 以服务端确认更新为已支付、待发货。微信收银台为平台原生能力，不绘制假收银台或把前端回调当支付成功。
2. 积分默认“不用积分”。原生 radio-group 明示“不用积分 / 使用积分”，可用上限只读服务端报价。点击使用只重算报价，不创建订单、不扣款、不预占积分。显示服务端实际抵扣，前端不根据积分上限推导应付金额。
3. 重算前废弃旧报价和金额，保留选择、原报价上限与仅展示的结构快照以避免选项消失或页面大幅跳动；旧金额用占位符替代；重算中禁止重复选择、改数量和提交。失败后没有可提交旧报价，可重试确认或选择不用积分。账号变化清理积分、地址、报价和幂等键；页面离开或请求过期后迟到结果不能恢复旧金额。
4. 地址、商品、数量变更或报价过期重新确认，积分重置为默认不用；对已确认的新金额再次提交。零可用积分禁用“使用积分”；旧响应缺少上限则不推断余额。购物权益与积分仍不混用。后台余额、20%上限、FEFO、库存、订单锁定、退款和奖励规则未修改。
5. 配送售后默认两行摘要，纯文字“详情 / 收起”，44px 点击范围和 aria-expanded 保留。只有已知、已批准的履约快照版本显示“大陆包邮 / 72小时 / 7天无理由”；未知版本直接完整展示服务端快照，避免套用旧承诺。完整地域、密封与完好条件、退货运费继续可查。
6. 待支付页只留状态、截止时间和订单号；底部固定金额与微信支付，避开安全区。取消、付款结果查询、异常恢复继续保留。已支付页由实际发货状态说明下一步，删除重复的“付款成功可在下方…”。
7. 订单处理记录改为主动展开，避免三组空记录占屏；退款区有记录、读取错误或实际测试退款流程时展示。处理结果未知时的重试、查询和客服入口不隐藏，也不把空记录解释成操作失败。
8. 全局 text-button 改为透明无框文字，同时修正设置 inline-action、历史内容重试样式的局部覆盖。商品、结算、积分兑换、售后的加减数量也去掉边框和底色；44px命中范围及上下限状态保留。主按钮、原生选择、表单和可选卡片按语义保留清晰状态。仅复用既有按压反馈，不在交易环节增加装饰动效。

## 全面排查的范围与修正

`copy-scan-summary.json` 覆盖 41 个已注册原生路由和 4 个组件 WXML，131 处显式共享文字按钮。该数字是静态使用点，不等于 131 个原生状态均已实测。

| 位置 | 问题 | 最小修正 |
|---|---|---|
| 结算 | 长积分说明、预占术语、重复支付提示、常驻倒计时 | 二选一 + 实际抵扣；商品倍率一行；正常支付提示删除；过期恢复仍显示 |
| 待支付 / 已支付 | 状态重复、长篇履约规则、付款入口在页尾 | 精简状态、履约折叠、固定底部付款 |
| 订单列表 | 标题与空态重复解释 | 去重复标题，空态保留浏览商品 |
| 我的积分 | “来源核对”等内部说法、任务说明过长 | 待处理奖励、购物和邀请一句话；完整积分规则仍集中在规则页 |
| 社区关注 | 空态重复描述频道工作方式 | 一句“关注作者后，在这里看新动态” |
| 社区编辑 | 未保存修改提示重复、长段申诉说明 | 保留未保存损失和申诉入口事实，压缩文字 |
| 推荐关系 | 解释过长 | 保留“确认后不能更换推荐人”关键后果 |
| 设置 | 关于区域混入订单状态说明；小文字操作有边框 | 账号ID提示精简；文字无框 |
| 客服附件 | 反复解释“先选图、预览、决定发送” | 删除重复解释，实际预览和发送仍是两步 |
| 护理、记录、协议、隐私权利、佣金等 | 部分长文为真实权利、风险、未知结果或不可逆后果 | 不按字数机械删除；私人记录、可选授权、退款/退出/注销/真实与模拟边界继续保留 |
