# 会员卡与护理记录入口调整

依据本轮用户明确指定的布局，落实于原生微信小程序。PRD 附录 M：`PROFILE-CARE-01`、`PROFILE-CARD-01`、`CARE-ENTRY-01`。没有新增会员等级、积分规则或资料授权。

“我的”的主要任务是查看会员身份与资产；“护理”的主要任务是完成护理和回看记录。此次明确移动导航归属，保留现有路由、后退与登录恢复机制。普通已登录会员、商业会员、资料同步中及读取失败分别由服务端真实状态投影，不从昵称或管理能力推断会员等级。

## 页面和视觉

“我的”保留头像、昵称、设置与原有服务列表。顶部原来的护理卡和独立积分卡合为一张会员卡：上方为 CISME 字标与会员身份，中部为可用积分及“积分明细与兑换”，下方显示冻结、预占，存在到期／欠分时再展示真实提醒。卡片使用现有梅紫基调、深浅层次、1px浅边和静态细弧线，避免增加独立组件、外部字体或图片依赖；整张卡只触发一个积分入口。

“护理”保留原背景、四步、保存与调整逻辑。下方胶囊右侧为梅紫“详情”和现有箭头，独立原生button、垂直居中，实测56×44px。点击区参考 [W3C 目标尺寸增强说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html) 的44×44 CSS像素建议，结合仓库现有44px原生触达规范落实；这不代表完成全部可访问性认证。官方微信button在线文档本轮无法通过浏览工具打开，具体组件编译与点击由本机官方开发者工具核验。

布局使用现有 `--cisme-plum`、`--cisme-motion-press`、`--cisme-hit-target`，卡片沿用原品牌暗紫层次。数值字号大于辅助信息，身份不挤占积分；长昵称允许换行，长积分采用原有紧凑字号并保留完整数字。卡片和胶囊按压反馈短暂改变透明度／底色，减少动态效果时移除过渡；没有循环装饰动画。

## 状态与交互合同

| 触发与状态 | 界面与恢复 |
|---|---|
| 资料或积分首次加载 | 保留骨架；没有确认的积分不渲染成0。核心失败显示重试，订单、客服及设置仍保留 |
| 普通／商业会员 | 身份取现有资格读取；同步中及失败明确显示。本人同一会话切回时保留已确认卡片，迟到响应不覆盖其他身份 |
| 点击会员卡 | 进入原积分页，使用现有导航去重与失败反馈；不进入护理记录 |
| 今日已记录／未记录 | 胶囊继续显示服务端真实状态，详情均可进入既有护理记录。不会因打开详情创建日常记录或开始周期 |
| 护理读取失败 | 胶囊诚实显示未更新，详情保持可用，原有刷新入口保留 |
| 游客点击详情 | 仅在本次明确点击后核验身份并保留目标；护理首页不自动跳走 |
| 详情重复点击／导航失败 | 首次占用，重复点击不重复入栈；失败释放占用并提示重试 |
| 护理／建档弹层显示 | 背后入口不可点击，辅助技术隐藏沿用现有弹层语义 |

图标为装饰，按钮保留说明性aria-label。颜色与“详情”文字、箭头共同表达入口；没有用色彩代替文字。系统字号采用原生page-meta与rem，布局允许换行，不强制截断。实际系统大字号与320px机型本轮未实测，不能写成通过。

## 验证范围

- 当前原生包41路由、主包约1.37MB；TypeScript、包预算、接口契约通过，4份官方WXML/WXSS编译摘要。
- 4个针对性测试文件共103项通过，覆盖原有身份／余额／重读稳定性，以及新增入口的读取失败、重复点击、游客、弹层与导航失败恢复。未为外观编写镜像测试。
- 官方模拟器390×844、375×812、430×932截图；实际原生点击验证会员卡进入积分页、详情进入护理记录页；长昵称及2147483647边界积分完整显示。
- 375×667的macOS模拟器预设尝试因自动化连接超时未完成，原机型已恢复，原始尝试独立保留，不作为通过证据。
- 所有本轮截图采用完整拦截的合成数据，850等数字不是会员实账。没有向真实服务器写护理、积分、订单或资料；每组结束恢复原会话、网络请求和原始iPhone预设。
- 当前源码哈希及逐项结果见 `verification-summary.json`。全41页逐态、真机与实际系统字号矩阵仍未完成，历史截图未重绑定。

本轮只改原生呈现与导航，无服务端、数据库、积分规则变更。尚未执行新版体验版上传。
