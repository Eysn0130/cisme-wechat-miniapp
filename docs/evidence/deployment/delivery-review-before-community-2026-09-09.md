# CISME 全面审阅与交付清单 · 2026-09-09

当前可交付的是原生小程序工程、已联通数据库及对象存储的云端 API，以及可复现的测试与部署证据。尚未达到“团队扫码可完整验收的体验版”，更未达到正式发布。下一步应集中打通「真实登录 → 体验资格 → 护理 → 邀请/任务 → 上传 → 人工审核 → 进度」这一条闭环，暂不扩展交易和公众 UGC。

## 本轮已完成

- 修复云调用模式下错误启用开发身份/本地协议夹具：即使运行在 DevTools 或受控真机调试，设置了云目标后也必须使用真实微信身份和正式协议版本。
- 修复媒体写入、完成确认、删除和投稿状态之间的并发缺口：统一先锁投稿，再锁媒体；对象写入与校验期间保持锁。并发确认复用结果，失效/已删除/已替换授权不能恢复成当前媒体，已提交材料不能继续写入。异常处理不会在释放锁后删除另一请求已确认的文件。
- 使用真实 PostgreSQL 锁等待验证“校验时旧上传令牌重放”被阻止，同时覆盖重复确认、删除后确认、已提交状态和临时存储故障重试。
- 对真实存储执行最小探测并清理探测对象：预签名 PUT 可写可读，但服务忽略 `If-None-Match: *`，重放仍返回 200。因此没有启用直接覆盖最终证据文件的方案；移除探测新增的未使用生产依赖。
- 在 Stable 微信开发者工具中实测 `wx.cloud.callHTTPFunction` 传递 multipart ArrayBuffer，SDK 返回 `-401003 parameter should be object instead of arraybuffer;`。此方案不能作为 `wx.uploadFile` 的替代。探测使用不存在的媒体编号，无会员、协议同意或业务文件写入。
- 服务端并发修复已通过官方微信 CLI 部署到 `cismeApi`（5,671 文件、33.9 MB）；部署后原生云调用复测 ready 200、Feed 200、未登录业务状态 401。云端没有伪造会员写入，写操作并发验证限定于专用测试数据库。
- 更新当前源码验收哈希，并保留旧验收记录；新源码的视觉和设备状态仍诚实标为 blocked。

## 建议执行顺序

1. 收齐主体及协议资料，同时落实上传 HTTPS 通道；这是解除身份与文件两项主阻塞的最短路径。
2. 接入并验证原生登录及上传，部署独立 Worker 和日志，完成后台人工审核闭环。
3. 冻结源码，执行当前哈希的逐页/真机验收，修复后按新哈希重新验收。
4. 上传并设置团队体验版，完成指定成员扫码验收后移交。
