# 普通社区发帖不依赖消息推送的实现

用户反馈微信公众平台保存消息推送持续“系统繁忙”，要求先不启用推送完成发帖。沿用 miniprogram-development Skill，选择显式配置的微信1.0同步图片检查作为临时路径；[当前微信官方文档](https://developers.weixin.qq.com/miniprogram/dev/server/API/sec-center/sec-check/api_mediacheckasync)说明1.0于2021-09-01停止更新，v2异步仍为默认。未把它当作新的v2接口或虚构轮询接口。当前真实账号的PNG 320×320和JPEG 1600×1200合成图均收到HTTP200、errcode0；未配置消息推送、创建业务内容或导出凭据。探针不等于真实会员发布或手机验收。

同步接口检查的去元数据、方向纠正、完整JPEG不超过1MiB，精确同一份字节才用作公开详情；缩略图从此图生成。每次真实通过独立记录provider=wechat_v1_sync、私人原件SHA256、公开图SHA256和字节数，没有虚构v2 trace。缺失结果、服务错误、超时、违规及摘要不符均保持私有；存稿可重试。原v2回调路径及WebP处理保留，新模式无自动降级。原生小程序文件没有修改，不继续先前暂停的列表图片性能排查。

UGC-NO-PUSH-01至05定义本轮边界。旧UGC_MODERATION_READY不再阻止普通发帖启动；发布后管理权限保持不变，不给真实会员补造管理能力。开启脚本仅记录用户本轮真实授权、对应告知及体验community开关，不声称法务部门审批或平台推送登记，不创建会员同意、原帖发布意愿、权限、资金或验收帖子。旧私人草稿仍只在本人主动点击去发布后进入安全检查。

切换使用绑定当前836/schema106的新增守卫，保护原106份SQL／包／迁移器与完整依赖树，107仅扩展扫描provider枚举。先排空两个体验服务并取得认证加密的同机数据库保护点；全部业务行摘要在迁移前后相等，再只允许两份新告知、旧告知active状态、一个有期限可撤销的启用记录、community开关和一条部署审计的精确差异。其他用户事实（含并发新增稿）、同意、权限、私密资料、原密钥及正式服务必须保持。失败留保护点并停止继续切换，不自动恢复旧数据库覆盖新事实。

当前源码回归包括文字／九图直接发布、精确图片字节和MIME、关注流、删除访问、失败／模糊结果、重试、草稿不自动发布、删除中迟到结果、篡改摘要拒绝、旧v2回调和生命周期、107回退重放，以及启用事务原子性。实际安装、CI和手机验收范围以随后单独收据为准；本说明本身不冒称已部署或整套真机通过。
