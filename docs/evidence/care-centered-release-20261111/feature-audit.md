# 当前功能启用核对

核对时间2026-11-11。依据PRD §7.9 PTS-CLUB、CARE-CENTER/USAGE-REVIEW、RELEASE-PARITY；有效运行配置见runtime-dependencies.json，真实公开接口见public-before-deploy.json。静态环境默认值不是运行开关最终值：积分由已有数据库运营控制生效。

| 业务 | 核对事实与本轮处置 | 验收边界 |
|---|---|---|
| 微信身份/建档 | 真实微信身份路径与加密问卷在用；游客不强制跳转；首次建档完成后进入护理，生日月日选填 | 本轮首页游客原生检查；原有真实身份不伪造重新注册 |
| 手机号 | 原开关false；真实App/独立密钥、官方token与接口查询配额均可用，启用可选绑定 | 原生授权拒绝仍登录；不以查询配额当作付费资源余额，代理未取号，需本人实际授权才能核验真实手机号 |
| 护理/记录 | 产品多选、同日调整、当日服务器日期与历史查询；真正周期继续四步+自我感受原子提交 | 原生全部拦截合成数据；真实周期/真机未宣称验收 |
| 护理周期暂停 | 服务端功能与权限/版本守卫已有；当前缺CARE_PAUSE_POLICY_VERSION/MAX_DAYS/REASON_CODES，暂停不可用 | 这项缺经营配置而非“体验版”限制。现实现超过上限需客服复核；不能随意设最大值并忽略超期恢复。下一步确定版本化时限、超期恢复处置与本人确认文案后接线；现有周期与历史不改写 |
| 日常/连续积分 | 运营开关真实开启；暂停奖励也可存记录，金融来源待恢复处理，按来源显示回执；晚到连续日补奖、已发不重复 | CI隔离数据库验证，真实会员积分零验收写入 |
| 购物/邀请/生日积分 | 保留商品3倍、生日首单额外2倍订单快照、收货发分、原规则退款撤回与欠分 | 本轮全量CI覆盖；没有代理实际扣款、退款或提现 |
| 抵扣/全商品兑换 | 实际pointsRulesEnabled及pointsRedemptionEnabled均true；不是根据.env里的false推断关闭。正常未来商品自动适用；保留真实价格库存及FEFO/取消/退货 | 源码与隔离数据库验证；无虚拟商品、无伪造发货 |
| 商城支付/售后 | formal_commerce、真实支付和恢复能力true；已核实独立体验商户命令与恢复授权文件；旧“下单/支付未开放”三处文案修正 | 不运行真实资金验收；已存在订单不因部署改写 |
| 物流/履约 | shipping.query/upload及物流账号/轨迹/登记的本地授权存在；官方插件已批准，但本轮真实查询组件运力接口仍返回48001未授权。普通寄件回填/复制运单可用，实时轨迹不能声称接通 | 需在微信公众平台功能→物流服务→查询组件完成开通（平台条件由微信核验）；不能伪造30天交易条件，不推送未指定订单 |
| 社区/安全/媒体 | publicEnabled、draftsEnabled及UGC_GO_LIVE_GATE均true。普通新发布走真实安全检查；旧私人草稿不自动公开 | 旧communityPreview/socialPreview=false为退役预览路径，不盲开；COS直传false为受控网关上传路径，不等于不能上传 |
| 客服 | SUPPORT_AI_ENABLED=true且实际密钥配置存在；人工咨询路径保留 | 仅只读配置核对；不擅自给用户/运营发送消息 |
| 佣金/购物权益/真实转账 | 正式单级关系、资格、计提、退款与管理源码已有；当前formal状态明确不提供隔离转账/购物权益结算 | 真实转账只有隔离测试实现，缺正式商家转账场景/收款人资格、税务/净额、付款及追偿规则；不能启用synthetic-zero-withholding或模拟支付。需要这些实际依赖及明确金额/订单的资金验收授权 |
| 管理/隐私/导出 | 保留服务端能力授权、本人导出/删除/注销、保全和恢复抑制；官方与个人身份分开 | 不按昵称授予权限，不用此次开启复制用户同意 |

全部功能的当前41路由/状态、iOS及Android真机、大字号验收仍未完成；受控体验上传不能被描述为正式审核发布。以上缺口不被“全部开关true”掩盖，也不阻止已有真实依赖的功能启用。
