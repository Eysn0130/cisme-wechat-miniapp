# 登录资料恢复与用户表格自适应

依据 PRD AUTH-PROFILE-CONFIRM-01–03、UM-02。保持同一登录页内的手机号、头像选择、微信快捷昵称确认，不增加独立资料页。

只读核对发现 No.00010、No.00011 均已有真实微信身份、已绑定手机号、已完成问卷及100可用积分，但尚无 member_profile 行，没有头像昵称保存审计。是资料未完成保存，不能通过管理展示补出真实微信头像或昵称，也不以问卷完成推断资料完整。未获得客户端版本/用户点击轨迹，不能断言当时每次真机操作经过哪条分支。

源码发现并修正的绕过路径：已有会话的“继续”不核对资料；重新进入非根登录页未恢复资料确认；离开未完成登录后仍可携带会话进入护理问卷；护理/我的没有按实际资料补齐状态返回登录。现在按原canonical账号读取真实已保存字段，已绑定手机号不重复授权，完整资料不重复询问；保留会员编号、问卷和积分。用户退出未完成登录后仅公开浏览，重新登录仍识别原账号。

微信快捷昵称以原生 form submit 的最终 value 保存，避免输入框已填值而 input/blur 状态尚未更新时提交旧昵称。头像继续绑定当前会话与会员，使用既有版本校验的同一次资料保存。昵称/头像只能在用户本人选择确认后写入，不伪造、代填或后台获取。

表格：用户列和数据列分配剩余宽度，末列固定触达区域并对齐右侧；较多字段维持原最小列宽和横向滚动，表头与各行使用同一尺寸规则。

所有本轮原生受控资料均为合成，真实库只读。新证据必须绑定当前包哈希；未连接真机，真实微信授权弹窗、微信昵称快捷栏及实体设备操作仍待验。

Owner 随后追加商城卡片精修：通过已安装 Taste 与 Impeccable 的 scoped polish，圆角44rpx缩至28rpx，加入有偏移的淡紫灰单层阴影，图片display:block，保持原商品事实、价格和路径。设计依据与范围见 shop-design-review.md。
