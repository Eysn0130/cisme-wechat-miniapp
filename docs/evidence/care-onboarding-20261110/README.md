# 首次账号护理建档 · 第 3 稿落地

用户已确认：选择第 3 稿、增加“医生推荐”、移除“信息用途说明”和“稍后再填”，完成基础建档后进入护理。文档中的历史积分与选品建议只作为资料来源；本次用户确认和当前 PRD 的 `CARE-ONBOARD-01` 至 `08` 为本轮范围。

当前已完成原生小程序、API 和数据库迁移源码，并通过隔离数据库与原生模拟器的分项验证。本轮没有部署服务器、迁移正式数据库、上传体验版、写入真实会员、兑换商品或发放积分。

## 当前行为

- 新账号创建与待完成档案在同一事务中建立。进入护理页自动展示建档弹窗，关闭、稍后再填和首屏说明链接均移除。游客原授权入口保留；既有会员不强制补填，可在设置的个人资料中主动打开护理档案。
- 每次“下一题”保存成功后前进；退出后从服务端已保存的题目恢复。上一题可核对答案；网络结果不明时保留原请求重试，并校验版本、会话与身份。
- 来源、护理困扰、选购因素为多选，最多 3 项。独立选项互斥，不默认预选，不将“未回答”“跳过”“不愿透露”“不确定”“未授权”混为同一事实。
- 个人情况可跳过。护理困扰、掉发和头屑前有独立可选授权；不同意仍能完成基础建档。此授权与已删除的首屏说明链接不同。
- 以当前登录会员为档案所有者，来源中的 `doctor` 仅保存自报“医生推荐”，不绑定推荐人、医生身份、权限或佣金。
- 所有答案使用 AES-256-GCM 加密，AAD 包含领域和会员 ID。授权证据与操作回执分表保存，回执不保存答案快照。已接入本人导出、明确范围的资料清除和注销处理。
- 第 10 题保存套装偏好；实际兑换需另行接入已核实的活动、商品、库存和费用规则。本轮不新增积分奖励或订单。

## 接口与存储

三个接口均要求当前会员会话：

- `GET /v1/me/care-profile`：题目、独立授权文本和本人的当前草稿。
- `PUT /v1/me/care-profile`：逐步保存；需要稳定的 `Idempotency-Key`、问卷版本、`expectedVersion` 和当前题号。
- `POST /v1/me/care-profile/complete`：校验必填与显式跳过状态后完成建档。

迁移：`db/migrations/202611100004_member_care_onboarding.sql`。`member_care_profile` 是每会员唯一的加密当前档案；`member_care_profile_operation` 保存幂等回执；`member_care_consent_event` 保存授权决定和文本证据。发生未知重试时返回当前最新投影，不把旧回执当成旧答案覆盖回去。已有数据时迁移回退会拒绝直接删除表。

部署需先备份并按现有独立环境流程迁移数据库，再部署后端和匹配的小程序包；须核实该环境的私有加密配置。未执行该发布步骤前，正式会员不会收到新弹窗。
