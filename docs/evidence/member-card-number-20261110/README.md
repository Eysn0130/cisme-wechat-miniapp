## 编号闭环

现有系统只有UUID，新增独立 `member_card_number` 表作为本人可见的会员卡编号；不重写member、微信身份、订单、积分、权限或官方发布身份。数据库唯一身份序列，在会员创建同事务内分配，已有会员按created_at、id一次性建号。编号发行后不可更新，不循环复用；失败事务可以跳号，编号不等于人数或等级。序列与唯一约束的依据：[PostgreSQL identity](https://www.postgresql.org/docs/16/ddl-identity-columns.html)、[sequence](https://www.postgresql.org/docs/16/functions-sequence.html)。

后端以字符串最少5位返回，超过99999或JS整数精度范围仍保留全长。仅本人`/v1/me`、`/v1/me/profile`、bootstrap、设置和本人数据导出包含，不增加按编号查人的接口，也不公开到社区作者。用户不能从资料更新请求更改编号、借编号取得权限。设置同时保留原账号ID供既有客服／数据权利查询使用，避免把UUID误当新的卡号。

114号迁移仅新建编号映射并建立注册触发器；下行回退拒绝删除已发行编号。运行时回退可继续兼容保留的加法模式。体验和正式数据库独立分配，不能把体验映射或资产导入正式会员。
