# PR3 合成删除显式范围迁移

基线：`docs/product/CISME-产品需求文档-PRD-V2.1-R4.md`（正文 R4.2）P20/A11 与 §7.7。自由文本可说明诉求，却不能可靠地授权删除某一个具体数据类别。因此在任何合成擦除执行前，新增一个结构化、不可事后改写的范围码；现有未带范围码的请求继续保持非执行状态。

- 迁移：`202609140002_privacy_request_explicit_scope.sql`，只为 `privacy_request` 增加 nullable `scope_code`、约束与身份/不可变触发器。目前唯一值 `member_profile_handle_v1` 只可与 `kind=delete` 组合，且请求会员须关联 `dev_test` 身份。无默认值，不重写任何现有请求，旧应用可继续写入 `NULL`。
- 隔离验证：本轮专用 `cisme_pr3_local_postgres_20260914` 的 `cisme_pr3_test` 合成库；空库/N-1 前向迁移和合同校验、非开发身份/错类型插入拒绝、scope 更新拒绝均通过。候选代码 365 单测、172 隔离集成测试、build 和 OpenAPI 合同检查通过。
- 数据影响与兼容：只扩展 schema，不更改既有 `plan_only`/`dry_run` 作业、成员资料或生产数据；无正式环境执行授权。已存在的自由文本删除请求没有被自动映射为资料字段删除。
- 恢复：无非空范围码时 `down` 可删除此增量；已有非空请求时 `down` 明确拒绝以免丢失授权事实。应保留前向兼容应用或从本轮专用备份恢复到另一隔离库，不强行清除请求来获得“回滚 PASS”。任何远程数据库迁移仍需单独目标、备份和授权。

本提交仅包含 schema/契约/测试/清单，不代表擦除执行器已实现或已验收。
