# 管理工作台交互与视觉约定

基线：PRD V2.1-R4 §3.2（服务端能力、行/字段范围和职责分离）、§6.6（现有业务后台）、MGMT-ENTRY-01；本轮仅覆盖已实施的管理能力。官方精选评论管理不等于恢复普通UGC发布前人工审核。

设计方向：原有紫色品牌、浅底原生工作台；分组列表承载导航，状态优先于装饰。密度适中，不增加营销式大标题、重复卡片、渐变或新组件依赖。

依据：mobile-ui-ux-designer 主导状态、路径、键盘与恢复；[taste-skill](https://github.com/Leonxlnx/taste-skill)与[Impeccable](https://github.com/pbakaus/impeccable)用于辅助视觉审阅、polish和删减文案。沿用项目字体/图标/间距和120ms按压反馈。外部[触控目标规范](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)AA最低24px；本项目继续采用44px目标，不把44px表述为AA强制值。

| 场景 | 约定 |
|---|---|
| 管理中心 | 待办逐类展示真实数量；不相加有重叠的案件；按交易、会员、服务分组入口，只呈现有效权限；积分单权限不得与空入口状态冲突 |
| 列表/详情 | 首屏展示可处理对象、状态、金额；清晰分隔；长名称允许换行，编号可断行；下一页、刷新、详情用文字，保留44px点击范围 |
| 筛选/模式 | 文字选项与选中下划线或低饱和底色；用aria-selected/pressed表达选择，不靠外框区分 |
| 提交 | 保存/登记/核准等主动作保留实色；辅助、取消、关闭无外框；改变资金/资格/库存或删除的真实确认及处理依据保留 |
| 商品 | 读取和导航绑定当前账号/页面/已加载商品；分页去重；草稿冲突、资质/上架/库存独立事实保持 |
| 北京时间 | 经营日期及费率填写与序列化固定+08:00，防止设备时区改变生效日；无效日历日期拒绝 |
| 结果未知 | 不把网络中断等同失败；使用原请求核对/重试，禁止修改不明结果的原请求，避免重复业务动作 |
| loading/error/empty | 核验期间关闭失效操作；显示明确重试；无权限清除敏感快照；空列表给事实，不制造演示成功 |
| 隐私与财务 | 回复、任务执行、渠道受理、真实资金终态分别展示；导出/删除和退款不能因去文案而被误认为已完成；另一人复核及服务端权限保持 |
| 原生验收 | 用官方开发工具，390/375两宽度，真实胶囊/安全区，全HTTP拦截合成场景；基线与最终包各自哈希，不把模拟接口当真实资金实测；还原账号、存储、机型与页面 |

用户已明确要求直接精修并准备发布；沿用已授权的main合并和体验版上传。实际扣款/退款/转账未指定订单与金额，本轮不执行真实资金动作。全路由真机及正式平台配置另按具体证据记录，不能以本轮局部模拟验收代替。
