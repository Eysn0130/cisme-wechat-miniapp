# 管理中心全页精修与业务连通核验

用户要求：延续无边框辅助按钮、精简机械文案和商业成品标准，对原生管理中心及关联管理页面进行全面精修与业务排查，为正式上线准备。分支基线 main b9b873a，前版0.1.40已确认上传；原生源包 c62ae3db。本轮使用 mobile-ui-ux-designer 主导交互，design-taste-frontend 与 Impeccable 辅助视觉。用户明确要求直接推进，按已有授权实施，不增加依赖或Web架构，不恢复被弃用的投稿/领奖/旧护理界面。

步骤：逐项梳理中心入口→列表→详情→提交→状态恢复；先保留源界面原生截图，再收紧排版/分组/字号/文字操作，识别实际权限和运行状态。对商品、订单/履约/售后、客服、会员、积分、财务、隐私及精选评论分别追踪读取与命令契约，修复最小断点。测试采用独立数据库和全HTTP拦截的原生合成场景，正式资金动作需用户指定订单/金额/次数，不能拿真实客户试验。具备真实依赖的能力不因“体验版”名字被关；缺口记录具体配置/微信权限/备案及下一步，不伪造开通。

已见问题候选：管理中心采用多张重复卡片和“进入处理”等冗余文案；待办使用plain边框按钮；空管理入口判断遗漏canPoints（积分管理存在时仍可能出现暂无入口）。后续逐页按真实状态核对，再决定修正范围。

范围：13个management*路由（共15个核验页面）（含客服两页），以及中心实际链接的售后和精选评论管理等关联路径；只在现有PRD生效范围内完成。头像/AI客服已在0.1.40交付，保留实际发送人、回复目标、版本和幂等边界。
