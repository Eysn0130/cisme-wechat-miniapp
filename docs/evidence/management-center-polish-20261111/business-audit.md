# 原生管理页面的业务连通核验

范围为13个management路由和中心实际链接的售后、精选评论，共15页。依据PRD V2.1-R4 §3.2、§6.6、会员积分相关章节及MGMT-ENTRY-01。所有权限由真实服务端授予；运营名称、页面参数不授予权限。本轮没有数据库迁移或服务器业务改写。

| 路径 | 核验与本轮处理 |
|---|---|
| 我的→管理中心→工作台 | 保留当前authority核验；仅积分管理可用时不再显示空入口。待办逐类跳到原有工作台/售后筛选，不合并重复案件数量；隐藏正常支付连接提示，保留异常重试 |
| 商品列表→详情→保存/资质/上架/库存 | 补齐账号与commerce context绑定、已加载对象校验、分页去重、权限撤销清空和导航失败的旧响应隔离。原有版本、草稿冲突、资质及库存事务保持；库存文本键盘可输入负数，修复原数字键盘不便出库的问题 |
| 订单列表→详情→发货 | 保留真实订单行、金额/地址权限和分轴状态；交寄登记及微信同步仍分别显示，不能把渠道同步等同已签收；原有版本/幂等及北京时间校验保持 |
| 履约→筛选/导出/XLSX预览→批次提交→单行订单 | 保留500单上限、收件信息专项用途、真实交寄时间、原批次未知结果重试和逐行反馈；减少重复文案和辅助按钮外框，不改变预览/最终确认语义 |
| 会员列表→详情→推荐/订单/公开内容 | 保留成员/本人购买/推荐归因的区分与服务端范围；全局及会员费率的默认显示、提交和确认均固定北京时间，拒绝日历归一化后的无效日期；原订单锁价锁费率、提议人/受益人不得自批保持 |
| 积分→兑换履约/倍率/规则/精选 | 仅显示对应capability模块；展开查看完整规则。结果未知保留原key与载荷，可重试原操作；不能改内容另发新请求。更换账号/上下文丢弃旧命令，403清空敏感快照。保留服务器版本、积分事件唯一性及两人复核；补齐运单、说明、版本/日期的前端校验。页面卸载后不持久化包含运单/说明的管理草稿；原事件/版本由服务器阻止重复生效，重新进入需读回核对 |
| 财务→待办→关联订单→退款/查原单 | 新增有order.read权限时的订单详情入口；补齐财务快照账号/context绑定，阻止账号切换后沿用旧待办发起决定，并拒绝中途返回的旧确认。北京时间展示。真实核准仍需原版本、处理依据、服务端权限与职责分离，未执行真实资金动作 |
| 隐私列表→详情→回复/补充/资料更正 | 保留回复与执行任务分离、版本和资料版本校验、权限撤销清空。期限按北京时间显示；保存回复不能伪装导出/删除已完成。正式自主导出/注销与受控历史执行路径沿用现有服务端权限，不向privacy.request.manage增加原本没有的敏感审批权 |
| 客服队列→会话→售后 | 队列按原服务端顺序，辅助状态无框；保留0.1.40实际双方身份/头像、不同客服、人工接入、只生成可编辑草稿的AI帮写及私有会话边界。聊天页本轮不重构 |
| 售后→案件→收件/质检/例外/退款审批→会话 | 保留原行级/动作权限、原请求重试和当前/旧地址事实；小按钮文字化。用户申请、管理员处理、退款完成分开；质检不自动恢复可售库存。未拿真实案件试写 |
| 精选评论→原文章/举报/隐藏/删除 | 文字操作与选中线，保留版本、原因、内容安全、删除确认和公开作者身份；历史待审分类不等于恢复普通UGC发布前人工审核 |

实测层次：完整本地单测3257通过/1既有跳过；原生全HTTP拦截的合成页面与交互；只读公网运行配置/401权限边界；随后CI隔离数据库验证既有服务端业务。前端截图不冒充实际支付/退款/物流平台成功。

## 正式发布剩余事实

本轮只读读回见runtime-readonly.json：体验API为真实商务协议配置，公开2款198/298元、各100库存、3倍积分；正式API健康，但orderFlow/payment=false、formalRecovery=true、公开商品为空。不能把管理界面精修或体验上传说成正式商城已开售。旧生产数据库/源码升级、真实库存跨环境分配、公众平台备案/隐私指引/合法域名与商户权限、真实物流查询48001和佣金真实转账依赖，见前次formal-readiness.md的具体计划；其未在本轮重新读回的内部项保留原时间范围，不伪造本次实测。

微信公众平台页面此前被浏览器安全策略拒绝，未绕过限制、未提交正式审核。全41路由的iOS/Android真机/字体矩阵仍为blocked；本轮375/390模拟器及合成流程不会把该门禁改成通过。主分支合并、体验上传和正式提审分别留回执。
