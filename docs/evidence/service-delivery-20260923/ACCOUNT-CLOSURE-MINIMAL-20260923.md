# 账号注销最小正式链路（2026-09-23）

本批仅收敛原 `privacy-rights` 的 `close_account` 类型；没有新增页面、审批链或管理系统。数据导出与删除请求仍保留在原流程，其正式执行能力不因本批注销实现而被声明完成。

## 已落地的行为

- 当前微信身份提交注销并在原页面确认后，同一事务关闭 `member` 身份、终止会员状态、禁用推荐码、撤销管理授权与活跃同意；旧会话及再次登录均被拒绝。
- 可直接清理的联系方式、资料与地址簿内容删除或匿名化；被交易报价引用的地址行只清空内容，保留引用。订单、支付、退款、售后及关联客服事实不作物理删除。
- 有生效法定保全绑定时，先关闭账号并隔离，保全范围内的资料暂存；请求记录明确告知保留原因，保全解除后的启动重放会继续清理。
- 注销后用户可通过原微信核验入口进入受限隐私请求，查阅处理记录并继续提出历史资料请求。`management-privacy` 仍是唯一管理入口。

## 恢复保护与生产装配

`PRIVACY_SUPPRESSION_DIR=/var/lib/cisme/privacy-suppression` 是 production 必需配置。目录须由 `cisme` 用户持有、权限 `0700`，位于数据库备份与应用 release 目录之外。每次注销先写入含用户 UUID、微信身份摘要和请求 UUID 的标记并同步落盘，再修改数据库。API 启动前重放标记；旧数据库恢复后，已注销身份不能重新登录或生成新账号，恢复出的活跃资料会再次清理。若备份早于注册而用户行不存在，身份摘要仍阻止新账号生成。

生产 systemd 单元须使用本批 `ReadWritePaths` 配置，并在候选环境中设置上述路径。`production-release.py` 的预检会拒绝缺目录、宽松权限或 systemd 未授予写权限的候选。标记目录必须有独立的站外备份和恢复程序；**仅恢复数据库、丢失标记目录的整机灾备不具备防再现保证**。正式恢复演练需要把标记目录先恢复，再启动 API。本批隔离测试模拟了旧数据库状态重放，尚非真实生产备份恢复证据。

## 验证

- 正式形态微信身份夹具：本人注销、旧 token 拒绝、再次登录拒绝、受限历史隐私入口可用；保留订单行、擦除联系方式与地址簿、停止会员资格。
- 法定保全：注销可完成，受保全资料不提前删除；解除后重放清理。
- 恢复：旧数据库把账号与联系方式恢复成活跃时，再次启动会重新关闭并清理；数据库早于注册时，身份也不会重建。
- 本批 `typecheck`、单元、定向隔离集成及 production release Python 守卫测试通过。当前原生 DevTools/真机验收范围仍以独立记录为准，不以这些源码测试替代。
