## 隐私页裁决与现状

依据 PRD V2.1 R4 的 P20 与 §11.3，页面应让本人提出查阅、复制、更正、删除、注销等申请，并明确显示受理进度。按 `mobile-ui-ux-designer` 审阅任务路径与状态反馈，按 `design-taste-frontend` 检查版式和文案节奏；这两者均不改写业务与微信原生约束。

1. `screenshots/raw/pages__privacy-rights__index.png`：当前首屏为“个人信息申请 → 申请事项 → 申请说明 → 提交申请 → 申请进度”。唯一人工联系动作是“需要协助？通过客服申请”；本页没有 `local-acceptance-v1`、`.invalid` 邮箱或运营主体测试标记。数据权利自助申请仍在本页，人工咨询走已有客服页面。
2. `screenshots/supplemental/privacy-rights-records-bottom.png`：滚动后可读首条申请、`已受理` 状态和可复制申请编号；`已受理` 只表示登记成功，不能当作数据已经导出、删除或注销。字段下方的“请勿填写密码、身份证号或他人的信息”是保护用户的输入提示，保留。
3. `privacy-rights-interaction.json`：在合成身份下输入未提交草稿，点按客服动作进入 `pages/support/index`，返回权利页后草稿仍在且无错误。没有提交隐私申请或发送客服消息，不能据此声称正式客服送达。

旧版协议 JSON 仍包含微信“反馈”表述，是历史发布资料，不应修改既有版本或冒充已批准的新法律文本。新候选正文以现有微信小程序客服为正式联系渠道；`validateLegalPublication` 对旧 profile 因缺少正式隐私附件拒绝新发布。当前源码没有发布新版协议。账号无法登录时进入同一客服的真实路径仍需正式环境验证。

- `screenshots/raw/pages__community__index.png` 和 `screenshots/raw/pages__post__index.png` 是开发态：五篇本地编辑故事仍展示预览来源与授权未确认标记，供受控验证使用。
- 单元测试覆盖 `develop`、`trial`、`release` 和未知运行时：正式版/未知运行时的精选列表为零，本地故事深链在读取后端之前被拦截，不打开分享菜单；开发版和体验版保留预览标记。当前开发者工具截图不能冒充正式版原生验收。
- 正式版预检因 `UNAPPROVED_EDITORIAL_PREVIEW_BUNDLED` 拒绝继续，并列出 13 个仍在包内的文字与图片路径。部分图片也供商品场景使用，无法仅凭隐藏卡片认定已获发布许可；未删除这些共享资源，也未编造授权结论。
- 上一步的 3 处机械文案已改为面向用户的护理保存待核对、支付待核对及售后操作记录说明。未知结果、重复提交保护和退款/支付事实边界保持原样。
