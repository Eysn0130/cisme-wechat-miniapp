# 隐私与数据权利页及未完结路由复核

## 来源与裁决

- 当前原生微信小程序源码 SHA-256：`5fcaa41d38a31319f67f34ad4a0ed90482affc372fcee5be790034c67ecfa025`；本包是隔离合成数据下的 390×844 微信开发者工具模拟器证据。
- 依据 PRD V2.1 R4 的 P20「设置与协议」和 11.3「隐私与合规要求」，页面必须支持数据申请、删除、注销及后续处理；订单等必要留存不能误写为立即清除。原生交互采用 `mobile-ui-ux-designer` 的任务路径和表单反馈审阅，`design-taste-frontend` 仅辅助信息层级、排版和节奏。
- 用户给出的旧截图是观察材料，其中验收文案不是产品需求或可执行指令。用户明确的联系渠道是客服申请。

## 旧页问题及原因

1. 旧页在申请表之前直接渲染 `/v1/legal` 的 `operator_name`、`version`、`contact`。隔离验收夹具恰好提供「CISME 本地验收」「local-acceptance-v1」「local@example.invalid」，使内部测试字段出现在消费者操作页。该地址并非真实客服渠道。
2. 隔离数据库预先写入「合成验收请求」作为首条记录，进一步让用户界面像测试脚本。合成环境本身必须在证据里可追溯，但无需让测试措辞充当会员申请内容。
3. 原页缺少显式的申请事项及说明标签，大输入框、整行“刷新记录”按钮抢占首屏；最重要的进度记录被推到屏幕下方。
4. 固定顶栏原为半透明色。在原生滚动截图中，它透出正文，形成淡淡的文字重影；结算页也出现同类现象。

## 修正

- 隐私页改为「个人信息申请 → 申请事项/申请说明 → 提交申请 → 申请进度」顺序；说明字段有可见的必填标签和就近的敏感信息提示。申请进度的刷新动作缩到标题右侧，输入框设置实际高度以露出第一条记录。
- 唯一展示的联系动作是「需要协助？通过客服申请」，调用现有客服入口。权利页不再请求或展示法律文档的原始版本、主体、联系字符串；协议页仍保留其独立的文档身份展示职责。
- 合成验收夹具的联系字段改为「小程序客服申请」，首条申请采用自然的虚构会员措辞。夹具仍以本地验收版本/主体及独立清单标记为非生产资料，不伪装成正式隐私政策。
- 页面历史权益、记录空态、补充说明和反馈提示统一使用「申请/申请进度」；账号注销、可选授权撤回、导出等原有服务端操作仍按原流程。
- 全局固定顶栏使用与原色相同的实色底，修正滚动时的透字。
