## 问题与最小修复

`before-post-loading-e627214b.png` 是真实旧包现场截图：顶栏下方插入“正在加载护理故事…”文字行。帖子从作者页或原生图片预览返回时，还会先清空公开内容，再绘制图片、作者栏及正文。其他页面也存在相同的清空、占位和临时行插入。

本轮检查了全部 40 个注册原生页面的加载条件、空状态、身份归属和返回生命周期，见 `route-source-audit.json`。修复包括：

- 帖子保留同一身份、环境、文章的公开正文、封面、图片尺寸和页码，并重新读取事实。同一版本、媒体和布局才按原有规则恢复阅读位置；撤回、失效、身份改变和失败仍按原有规则处理。
- 作者主页、积分、任务、审核进度、商城／商品、邀请、订单和个人社区活动保留已确认的展示。商品保留有效的规格和数量，收到新库存后校正；核验期间不能领取、提交、关注或进入结算。
- 四个底部页以及已确认的空社区、选中日期无记录、空订单和作者无公开故事状态，在刷新期间不先消失。投稿页已有草稿的顶栏副标题也保留。订单不再插入临时更新行。
- 30 个页面的首次读取共用一个不占内容高度的小指示器，替代挤动布局的加载文字行。初次读取、错误、权限变化、资金核验和操作结果仍有真实反馈。
- 已登录用户返回帖子时，评论入口不再短暂变成“登录后评论”。旧评论仍在离页时清除并重新鉴权；核验期间显示原入口文案或不含私人内容的装饰占位，禁止提交。`viewerHasSession` 只调整展示，不授予访问权限。

只增加展示归属辅助函数和共享加载样式，复用原有请求、组件和业务守卫，没有新增依赖、持久化缓存、接口或数据库变更，没有跳过刷新，也没有修改真实交易和公开 UGC 开关。资金核验、未知操作恢复和管理权限状态具有实际业务含义，继续保留，未宣称这些状态的内容或几何尺寸恒定。

需求对应 PRD V2.1-R4：`ED-DETAIL-06`、`COMMENT-ACCESS-01`、`PROFILE-SYNC-01`、`PROFILE-CARE-01`、`CARE-DAY-CALENDAR-03`、`BUTTON-MOTION-01`。
