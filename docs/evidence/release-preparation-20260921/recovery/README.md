# 一次性合成恢复与旧目标边界

`npm run restore:verify` 不接受任意归档参数；启动全新 PostgreSQL 和 SeaweedFS 容器、随机 loopback 端口、随机角色、随机数据库与桶。数据库及对象目录按 run/容器身份核验，退出仅清理本次目标。旧 55432/58333 不可作为启动器目标；compose 的旧服务需显式 legacy-manual profile，本轮没有启用它。

本次 `synthetic-restore.json` 记录 72 次迁移、一个合成探针的 dump → 故意修改 → 恢复 → 摘要/事实核对，以及一个合成对象的内存备份 → 删除 → 原样恢复。它验证恢复流程可执行，不证明生产备份持久性、加密密钥托管、RPO/RTO、灾难恢复或旧事故已恢复。生产副本和个人数据未参与此演练。共享旧数据库的数据影响仍未知、未恢复。

安全边界更正：本轮早期存储契约测试沿用了旧 SeaweedFS 58333 的 `cisme-contract` 桶，上传/读取/删除随机键的合成图片；不能称“完全没有操作旧 Docker 目标”。现在契约测试强制使用启动器提供的新实例/桶/随机凭据，API gateway 存储也使用具归属标记的临时目录。未读取旧个人对象或重置旧 PostgreSQL。

`npm run backup` 现在拒绝隐式对 compose 数据库备份。真实备份须先明确授权目标、加密/保留规则和恢复位置；本次没有运行现有生产备份脚本。恢复时不得危险 down migration、覆盖未知库或消除渠道已发生事实。首次发版无上一正式小程序版本时，采用停新交易、保留历史回调/查单/对账、兼容服务回退与修复发布；不能假设平台一定可回滚。
