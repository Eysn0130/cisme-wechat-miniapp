## Tool decision

- The project is the native WeChat Mini Program at `apps/miniprogram`; `project.config.json` declares AppID `wx4eac2d4fb11d299b`. No `wx.cloud` use was found in its code, so a CloudBase plugin would not help this release gate.
- The installed WeChat Developer Tools `wechatide` Skill is version `0.3.11`, logged in and version-matched. Its built-in `automator`, `debugger`, and `previewer` skills provide simulator navigation, selectors, screenshots, console/network reads, phone preview, and a real-device debugging entry. Use these official facilities for the existing project. `miniprogram-ci` provides preview/upload/build facilities; it cannot prove a phone's WeChat identity exchange or observed iOS/Android layout and interactions. A third-party automation wrapper adds no necessary capability here.
- Computer can read and operate the Mac WeChat Developer Tools window. The enabled Computer inventory exposes that desktop app, browsers, and no physical iPhone/Android control surface. A desktop simulator screenshot or a remotely opened debug panel therefore cannot by itself certify a physical device journey. The authorized user must scan and perform WeChat login/consent on each phone; device-side and server-side evidence must then be correlated to this exact package.
