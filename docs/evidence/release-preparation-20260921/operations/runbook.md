# 发布、恢复与值守操作稿（未授权执行生产操作）

当前 topology 的可证明范围：本机唯一工程、loopback 合成 API 与逐次新建 PostgreSQL/SeaweedFS。`infra/tencent` 是现有部署模板，不能由模板推断线上资源、域名 TLS、商户配置或 staging 已存在。本轮没有部署云服务、改商户权限或仓库规则。

## 候选和迁移

- `node scripts/package-tencent-release.mjs` 仅接受干净已提交源码；输出 `dist/tencent-release-<head12>`，已存在则失败，禁止 clean 覆盖旧包。
- API/worker/worker-once、锁文件、完整有序迁移及 up-only 迁移执行器一起做 SHA-256 清单；manifest 绑定 source HEAD/tree、Node 和源 lock 摘要。无秘密、环境配置和 DB 副本。manifest 是可核验材料，未签名，不能代替批准或可信分发。
- 候选目录内 `node migrate.mjs verify` 只核文件摘要，不连接数据库。正式 `up` 要求明确 DATABASE_URL、迁移批准引用与部署前备份引用；脚本不替操作者证明这两项真实存在。不得 down。持 advisory lock、限定 lock/statement timeout，已应用版本须为候选迁移前缀，逐迁移事务执行。
- 旧 schema_migration 只记录版本名，不能独立证明历史 SQL 没被修改；发布前仍须核对已有环境的受信迁移账本。新迁移兼容性须由合成升级/恢复及新 HEAD CI 验证。
- 生产部署/恢复另行授权。先验证备份可恢复与配置绑定；API/worker 用同一候选，工作进程停止必须等待当前事务结束。不可用 down migration 抹掉渠道事实。

## 监控及处置

既有 `/v1/admin/runtime-metrics` 返回进程内有界延迟分位数和存储操作成功/失败分母；本轮增加数据库聚合信号：Outbox/存储清理死信、支付/退款 Inbox、未知付款/退款、未决转账、账单异常及支付组成冲突。无对象 ID、原始载荷、签名 URL、OpenID、联系方式或秘密。权限入口沿既有 operator session，不开放公共监控。

出现异常的处理顺序：

1. 值守人按关联请求 ID、静态路由和渠道 Request-ID 定位；不要粘贴真实订单报文或完整 token。
2. 停止对应新命令能力；保持单独批准的历史回调、查单和对账 lane。未知不是失败，禁止自动换单号、退款、转账或解除未知操作。
3. 通过有权限的资金问题界面查询原始业务事实、Inbox 与账单差异。因 grant/凭据过期导致的 lane 停止，由负责人修复对应授权/配置，不能改结果状态。
4. 仅在权限、版本、幂等与已有事实允许时进行人工复核的原号恢复；真实资金仍由负责人另批并人工操作。
5. 保存处置引用和前后聚合变化，独立复核后关闭事件。

合成演练已验证“有隔离死信 → 聚合信号可见 → 无载荷泄露/无自动重试”。尚未配置告警接收人、送达渠道或做真人响应演练，不能宣称已完成值守闭环。阈值/SLA 未批准，当前信号只表示待核对事实；等待时长不生成资金失败终态。进程内 rolling P95/P99 不得平均成多实例分位数，也不能冒充设备端或线上地域数据。

## 首发停止和恢复

首次小程序正式版可能没有上一版可回滚。停止新交易、显示维护提示，保留依法处理的历史回调/对账；使用兼容服务端回退与修复发布。维护只读开关会拒绝包括回调在内的写请求，仅能在明确短时维护窗口使用并确认渠道重试，不能代替长时间的新资金停用能力。

## GitHub 治理（只读）

入场实时 main `protected:false`、rulesets `[]`、environments `[]`。本轮普通 PR + exact-head CI 后按已有授权合并，没有自行审批自己或伪造独立 review。后续 ChatGPT/GitHub 独立复核仍未完成。最小管理员方案：main 必经 PR、verify 必需、至少一名独立 reviewer、禁 force/delete；受保护部署环境约束正式凭据/审批。此稿不是修改规则的授权，本轮未执行任何管理变更。
