# 文字卡片分步流程与动效 contract

2026-11-02。依据用户四张参考图经根代理与实现代理核对后的步序，以及微信原生约束确定；本报告不声称重新走通 Rednote 的发布。025dfc921b79 的 7 张图片仅为改造前基线，不是此流程的验收。最新源码冻结后独立绑定包指纹、实际源码和原生证据。

## 四步与用户动作

同一原生 overlay 内只有 input、generating、templates 三个阶段，确认后交给既有 publisher，不增加新路由、长文能力、话题、@、位置或可见性设置。使用系统字、CISME 紫和原生胶囊安全区。

| 阶段 | 主动作 | 返回／取消 | 成立条件与事件 |
| --- | --- | --- | --- |
| 输入 | 大卡片直接编辑，右下角“下一步” | 左侧取消交 parent；既有“直接写正文”为次入口 | 1–300 grapheme；不截断粘贴或 emoji。Next预检不能用每字等宽估计拒绝合法窄字；真正单卡溢出由Canvas measureText严格判断。下一步只启动本地排版，不发 confirm。用户编辑发 change。 |
| 生成 | 真实 Canvas 排版、导出和文件检查；无百分比 | 取消立即回输入，保字和模板；不触发 parent cancel | 成功仅进入模板页。失败保留文本并可重试，不以旧 PNG 冒充成功。 |
| 模板 | 大幅 3:4 实际 PNG 预览、横向模板缩略卡、底部“下一步” | 左上返回输入，保字和选择；取消旧异步任务 | 最终下一步只确认当前文字／模板对应的有效 PNG，发一次 confirm。 |
| 发布 | 现有简洁 publisher | 沿既有私稿和退出保护 | 新 entry 标题／正文留空，图中文字不重复塞正文；既有正文不被卡片 change 覆盖。 |

输入“取消”仅发 cancel(contextKey)，由 parent 决定保留／保存私稿／放弃，不由组件保存或删除后端。输入“直接写正文”发 cancel(mode: body, contextKey)，由 parent 显式转换原始文字；既有正文不能静默丢失。模板返回输入与取消生成均是组件内部动作，不应误触发整篇退出。

## 原生布局与键盘

- 头部操作热区至少 44×44px。输入阶段顶部只保留左侧取消，独立44px；下一步按用户本轮位置修订复用模板页右下角112×48px footer，距右22px并避让底部安全区。标题服从剩余空间，不硬挤在几何正中。
- 输入正文不小于 16px，其他输入不小于 14px。短输入块在引用符号与计数之间垂直居中，避免固定 50px 顶内距将留白全部堆到下方；长输入可随 auto-height 撑高，由内容区滚动承接。大卡片随可用高度伸缩，底部独立主按钮不随内容滚动。300 字及单卡溢出均用真实校验，不静默裁掉换行或后半段。
- 原生 textarea 保留确认栏、cursor-spacing 和 adjust-position。键盘显示时沿用既有发布页规则收起footer，原生完成收起键盘后恢复右下角下一步；不手工叠加键盘高度。点下一步先结束键盘，再进入生成；模板预览按键盘收起后的可用尺寸计算。后台返回不自动弹键盘，不自动确认。
- 模板主预览保持 3:4，宽度不超内容区，可在短屏缩小。横向缩略卡建议宽 56–64px、间隔 8–10px，实际触达不低于 44px；选中同时用边框／底色和 aria，不只用颜色。模板页底部下一步按参考图右对齐，宽 104–112px、高至少48px，不铺满整行；输入左侧用现有关闭SVG，后续返回用现有chevron SVG，44px热区，placeholder使用既有muted #75697a。
- 不加“第几步”教学条或额外设置面板。原生胶囊、底部安全区、正文／图片至少一种、9 图上限仍由现有页面和真实状态决定。

## 六款自有模板与渲染

保留 plain／lilac／memo 的历史键，新增 minimal／care／border 可用。所有卡片由 CISME 自绘，使用文字、留白、底色、线条或边框，不复制第三方插画／字库。新增样式必须实际改变画布排版或装饰，不能只换名称。

主图沿现有真实 Canvas PNG 导出并检查 FS、尺寸与文件大小；任何模板溢出单卡必须明确返回错误，不截断文字。实现已选择单个离屏Canvas顺序导出六张真实PNG，全部成功再进入模板页；这个本地批次本身就是实际生成工作，不用固定秒数假等待。缓存键包含文字内容、模板和渲染版本。缩略卡使用对应真实PNG，禁止把未渲染CSS样式冒充生成结果。

≤24 grapheme且有2–3个非空显式段落时，先按基础字号测最长段，再按可用592px等比收小，最小46px、最大不超过原字号；重新设最终font后使用原严格layout校验。目的是尊重短句显式换行，避免末尾孤立一两个字，不保证所有短句都必须单行，也不改变单段与300字长文保护。

实现采用六张完整结果缓存，快速切换直接选对应的有效PNG，无需假装重新加载或人为防抖；选中态、主图与最终确认目标必须同一次更新。若未来某项需要异步重建，则立即清旧主图并禁用下一步，可用80–100ms合并连续选择。每项结果检查contextKey、账号／页面上下文、generation、文字版本、模板键和当前阶段；旧返回不得覆盖新预览，当前失败不以上个模板充当可确认结果。

模板返回输入后继续改字，必须使旧主图和缩略缓存失效。原文和模板未变且文件仍有效时可复用精确缓存，不伪造第二次生成。最终确认前冻结一次当前结果，重复点击不能发第二个 confirm；组件卸载后不能删除 parent 正在使用的已确认 PNG。

## 动效数值与中断

| 动效 | 建议数值 | 中断规则 |
| --- | --- | --- |
| 输入进入生成 | 160ms 淡出／上移最多 8px，ease-out | 点击后同步置 busy，避免双触发；取消不等待动画。 |
| 生成状态 | 不显示假百分比，不设置数秒假等待 | 如避免闪帧，可仅完成约 200ms 的呈现过渡；错误立即出现，不等最短时长。 |
| 成功进入模板 | 180–220ms 淡入，可上移最多 8px | 必须先有当前有效 PNG；取消／切号让旧成功失效。 |
| 模板选中 | 边框／底色约 100ms | 新选择立即成为唯一目标，旧图不能交互确认。 |
| 新预览替换 | PNG 就绪后 100–140ms 淡入 | 待生成区域保留尺寸，避免页面跳动；不连续叠放旧动画。 |
| 减少动态效果 | 无位移／缩放，淡变不超 80ms | 采用平台可用方式；不新增设置入口，也不宣称系统减少动画已实测。 |

生成取消是逻辑取消：Canvas／FS 操作若不能物理中止，仍须立即回输入并使迟到回调失效。所有定时器和过渡 completion 都检查当前 generation，不能在取消后跳回模板。页面隐藏、组件卸载或账号变化清 pending job；保留当前可恢复文本，不自动最终确认。重新显示可重建同上下文的本地预览，不能自动上传或发布。

## parent 边界

- 组件事件保持 change(text, template, contextKey)、confirm(tempFilePath, size, text, template, contextKey)、cancel(contextKey, 可选 mode: body)。进度和缩略渲染不发业务事件，组件无网络请求或后端写入。
- 根代理裁决为生成确认前零 POST：parent 维护隔离的临时文字；最终确认才创建／核对 canonical 草稿并上传。取消时若用户显式选存草稿，可将原始文字保存为私稿；请求结果未知沿既有精确核对，不假称撤销已发送操作。
- parent 独立 textCardText，不把 card change 写进 body。新 entry 的 PNG 成功后 publisher 标题／正文留空；“直接写正文”是显式转换。暂不增加 publisher 返回模板替换已有媒体的能力。
- 最终PNG已验证但canonical草稿回执仍等待时，parent保留该真实图的3:4预览与轻量“正在准备…”反馈，不出现header下空白，也不称已创建。失败停止spinner，保同候选／同createKey／原图和既有错误重试；无图body／save至少有等待反馈。只有有效canonical归属确认才交publisher。显式进入列表、另稿或新稿时统一清旧entry／pending／import／resume／context／handoff，迟到旧create不能接管新scope；不能把离开称为撤销已发送的新建请求。
- 已有 post 的备份可选 textCardText 和 6-key template 同样受 owner／post／version 和 7 日保留限制；未 post 输入只在当前隔离内存。不能存令牌，不能把旧账号或旧版本文字恢复到新账号。
- composer 类型、事件、备份和模板 normalizer 必须同步 6 键，不能让有效的新模板静默回落 plain；旧 plain／lilac／memo 继续可读。

## 新包验证范围

新源码绑定后分别记录输入、实际生成取消／失败、模板大预览及横向缩略、快切 latest-wins、返回保字、最终 PNG、publisher 新 entry 空标题／正文和零提前 POST。截图与受控调用只证明对应范围；真实键盘、手指滑动、VoiceOver、相机权限、真实审核和整体 40 路由仍须独立验证。此前 SDK／工具边界与图片工具截字异常不因新文本改造自动判为修复，也不把旧包 Canvas 或 edge 证据改标到新包。
