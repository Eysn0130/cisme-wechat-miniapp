## 1. 结论先行

产品方向不应是“把两份旧 PRD 的页面全部搬进微信”，而应是以原生微信小程序完成一个可验证的护理复购产品：真实微信身份 → 购买/资格事实 → 28 天护理 → 自愿邀请投稿 → 人工审核 → 条件积分资产 → 精选证据 → 复购。社区、交易、积分和 AI 都是这条主循环的条件能力，不是并列首页。

当前工程已经形成“身份边界 → 护理 → 邀请投稿 → 领奖审核 → 条件冻结积分”的本地契约纵切，并以数据库、对象存储契约与集成测试验证了独立公开发布决策；默认配置不会把外部投稿变成公开内容。开发者工具已现场完成真实服务端 claim 与同一草稿恢复，但媒体和后续审核状态证据仍分别属于本地存储契约测试与明确标注的视觉夹具，不等同于 iOS/Android 相册或相机端到端上传。基础 `share_id` 的访问与身份首触归因已补齐，但积分全生命周期、生产后台权限、交易事实与购买/退款归因、公网测试环境、真实微信登录和真机证据仍未完成。因此它只能进入内部代码与产品审核，尚不能称为开发版/体验版候选或完整 R0 生产成品。

## 3. 本轮纠正的错误

1. **运行环境错误**：原生端曾用 `wx.getExtConfig` 取得普通小程序 API 地址，体验版会得到空配置。现改为显式 `devtools/preview/trial/release` 公共 origin，非本地环境为空即失败。
2. **隐私入口不足**：媒体选择前未主动触发微信隐私授权，登录页用“继续即同意”代替显式选择。现增加隐私检查、显式勾选和官方隐私协议入口；正式法律文本仍保持发布阻断。
3. **财务门禁失效**：`POINTS_RULES_ENABLED=false` 只出现在健康检查，审核通过仍生成冻结积分。现改为关闭时不创建 reward_claim/grant/lot/entry，消费者端和审核台同步显示“不发积分”。
4. **紧急开关口径错误**：原工程把 identity/uploads/reviews/rewards 四个运维开关误称为 PRD 的四个业务开关。现保留三个运维开关，并新增独立 `submissions/rewards/redemption/commerce` 业务开关；未启用的兑换和交易默认关闭。
5. **发布级别混用**：原文只讲 CI 与生产上线，容易把开发二维码或体验上传写成“完成”。PRD V2.1-R3 已加入本地/开发版/体验版/正式版四级门禁。
6. **工具路线过度自动化**：原文默认 `miniprogram-ci` 优先，但当前精确版本有高风险旧传递依赖。现以腾讯签名、公证的官方开发者工具 CLI 为本机主路径，自动化包只保留隔离候选。
7. **领奖审核误触发公开发布**：原 Worker 监听 `submission.reviewed` 并自动创建 Feed，且把利益披露文本误当内容摘要。现改为领奖/积分审核不产生公开内容；UGC 门有效后，必须由不同 `review_lead` 填写公开标题/摘要、AI 使用声明和复核证据，生成独立发布事件，Worker 再校验许可、状态、素材和门禁。门禁关闭时事件保持待处理并记录错误，不静默公开。
8. **开发二维码身份与体验资格死路**：原生端曾把手机上的 `develop` 环境也当开发者工具，导致真机走假身份；同时无交易源时体验成员无法获得护理周期。现仅桌面 `devtools` 使用开发身份，任何 iOS/Android/HarmonyOS 开发二维码都走真实微信登录；后台新增基于唯一签收/测试履约证据、RBAC、审计和单开放周期约束的体验资格命令，不制造订单/收入/库存事实。

## 4. 仍是阻断，不得降级为普通待办

- 真实小程序 AppID、管理员/开发者角色、体验成员和开发者工具扫码会话。
- 独立公网 HTTPS 测试 API、数据库、对象存储、备份、监控和 request/upload/download 合法域名。
- 小程序后台用户隐私保护指引、正式服务条款/许可文本与法务版本。
- 真实微信身份、媒体上传、弱网、键盘、安全区、返回、权限拒绝和三设备证据。
- 交易 profile、支付/退款/物流/对账；在此之前购买主循环尚未闭合。
- 购买/退款归因与复购事实；在此之前北极星只能作为目标，不能计算真实结果。

## 5. 后续施工顺序

1. **开发版纵切**：取得 AppID 和公网测试环境，完成真实微信登录、隐私、上传、审核与真机三设备。
2. **体验版封闭验收**：只开放本表允许能力；记录版本/commit/AppID/环境/设备/trace；所有延期入口双端关闭。
3. **交易 ADR**：MAKE 是当前唯一规划方向，runtime 继续 UNSET；完成版本化实现、sandbox、退款/发货/导出和对账 evidence 后才可选择运行 profile。BUY 只在限时具名供应商 spike 通过现金基线后重开 ADR。积分预占/提交/释放/退款分摊只属于独立 redemption gate，不是选择现金交易 profile 的前置条件。
4. **复购与分享**：在现有基础 `share_id` 之上接入真实签收→护理→购买/退款→复购事实，再建立北极星基线。
5. **财务积分**：只启用 3–5 条已签规则；先完成解冻/冲销/欠分/到期/对账，再开放任何抵扣。
6. **公众 UGC**：内容安全、法务、成年人、侵权、AIGC 与审核排班门禁全部通过后，才逐项开放发布/评论/关注/搜索。
7. **AI/连接器**：只有人工工作连续 8 周达到 PRD 进入门槛，才启动只读 Pilot。

这条顺序刻意避免继续精修未启用页面，也避免把演示版变成假生产。成熟不是功能多，而是每个已开放能力都有权威状态、失败路径、权限、审计、运营责任人与退出方式。

## 6. 2026-08-31 原生交互与视觉范围增量

本增量不扩张 R0 功能，只收紧已经存在的原生入口：

- Account 的系统/顶栏 Back 与“暂不登录，浏览公开社区”是两个产品动作：Back 恢复受保护来源和路由栈；Browse 明确放弃身份流程并切公开社区。
- Back 恢复受保护来源后，该来源的自动鉴权重定向保持抑制，直到用户显式点击重试/重新登录；这同时覆盖 Home/Settings 单请求与 Profile 多并发受保护请求，避免返回后立即再弹 Account。新会话建立或显式重试会解除抑制。
- 身份授权步骤本身不是可点击入口，移除无 handler 的右箭头；身份请求只由底部主 CTA 发起，避免假交互和重复提交。
- “查看协议”保持独立至少 44px 命中区并显式居中；法律勾选仍由用户本人操作，正式法务版本缺失时生产身份失败关闭。
- 关键动作文字采用统一 UI 字体、16/20px 行盒、双轴居中与受控光学基线；这不改变 CISME 的宋体标题、珠光紫、玻璃卡片或深紫胶囊视觉真值。

## 7. 2026-09-01 真机调试与社区范围增量

- 增加受控真机调试通道，只服务获授权开发成员：同局域网可用私网 HTTP；异地协作仅接受 origin-only `https://*.trycloudflare.com` 临时隧道。私有编译条件必须显式携带 `cisme_remote_debug=1`，运行时同时满足物理设备与 `develop` 才能使用开发身份和本地法务夹具；devtools、trial、release 均拒绝该覆盖。
- 私网 origin 只接受 RFC1918 IPv4 的 origin 形态；localhost、公共 HTTP、带 path 的地址以及 trial/release 均拒绝。该通道不替代合法域名、真实 AppID/角色、体验成员、iOS/Android 验收或体验版上传。
- 社区生产面继续采用 Hero + 双列品牌精选、4:5 图片、人工审核/来源标签、唯一页面滚动和明确错误恢复。development/test 可展示带明确“测试预览”语义的推荐、赞藏、评论与关注；staging/production 服务端失败关闭，不把 QA 能力计入 R0 上线范围，也不开放搜索排序、公开作者页或个性化推荐。
