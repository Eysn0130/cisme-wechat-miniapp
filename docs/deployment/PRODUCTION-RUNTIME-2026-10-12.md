## 日常运行与变更方法

先在唯一工程中核对准确 commit、测试结果与不可变制品摘要，再在目标正式实例核对现有安装和私有输入。所有环境配置、数据库密码、AppSecret、私钥与备份密钥留在受限目录，不能进入本文件、Git 或命令输出。

可在获授权的正式机内只读检查服务与本机 TLS：

```sh
systemctl is-active cisme-api.service cisme-worker.service
systemctl is-active cisme-trial-api.service cisme-trial-worker.service
curl --fail --silent --show-error --resolve api.cisme.cn:443:127.0.0.1 https://api.cisme.cn/health/ready
curl --fail --silent --show-error --resolve staging-api.cisme.cn:443:127.0.0.1 https://staging-api.cisme.cn/health/ready
```

公网验收必须从外部网络进行，记录域名、时间、证书验证与实际 HTTP 结果；不能使用 `curl -k`、本机 `--resolve` 或关闭微信域名校验来声明公网通过。体验 API 3101 已绑定 loopback；现场生产 API 3100 与 PostgreSQL 5432 仍监听所有接口，由 UFW 阻断外部访问，不得开放这些端口。后续应在受控配置维护时将其收窄到本机监听。Nginx 变更先保存原配置，运行 `nginx -t` 成功后 reload，同时复测两个域名与生产服务 PID。

体验安装器默认 `preflight` 为只读，`apply` 只处理已绑定的体验资源。输入须是已经部署、完整校验的准确 release 目录；当前脚本固定 751f 制品，不能用它接受未来任意版本。遇到已有文件、数据库、迁移或所有权漂移，先分析真实状态；不得删库、重置迁移或覆盖未知文件后重试。未来体验版本更新要形成准确候选与相应变更方案。

生产应用升级继续使用 `infra/tencent/production-release.py` 的完整门禁：准确 main 与 CI、目标实例、不可变制品、SQL 审阅、私有输入摘要、新鲜备份保护点、所有写入者围栏及恢复资格。部署后读回实际 PID/cwd、迁移、Worker 心跳和业务事实。`deployed=true` 不代表交易、UGC 或微信发布已获准。

## 回退与故障处理

体验异常优先停止 `cisme-trial-api.service` / `cisme-trial-worker.service`，并按保存的上一配置移除或回退体验 Nginx vhost，配置检查后 reload，复测生产 API。保留 `/opt/cisme-trial` 的所有权、迁移与故障记录以及体验数据；不自动删除数据库或恢复生产备份。PostgreSQL 访问规则变更保留安装器的原始备份，仅处理已标记的体验规则，不能覆盖并发发生的其他规则修改。

生产升级失败须遵循已审阅的恢复模式。只有经过同数据兼容验证的旧应用才可在原数据库上作应用/配置回退；不得用旧数据库备份覆盖保护点之后的新事实。`forward-only` 失败时保持写入者停止，保留原失败回执，修复后重新 preflight、重新形成资格，并对同一不可变候选执行 `resume`。更换源码、密钥或配置不能伪称同一候选续跑。详细操作见 `infra/tencent/PRODUCTION-FORWARD-RECOVERY.md`。

本轮没有执行新的生产应用切换、生产数据库恢复或生产回退演练，不继承旧演练为本轮通过。
