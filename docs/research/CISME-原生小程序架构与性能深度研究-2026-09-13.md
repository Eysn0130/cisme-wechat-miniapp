# CISME 原生小程序架构与性能深度研究

## 执行结论

截至 2026-09-13，CISME 的正确主干仍是「原生微信小程序 → 自有 Fastify 业务 API → PostgreSQL 权威事实」，由独立 worker 处理可靠异步任务，私有媒体经受控对象存储边界。它符合 PRD 的 One-App、MAKE 自营和单一权威源决策；当前没有证据表明需要把核心服务拆成微服务，或把任一业务模块改写为 Rust。更可能影响体感的是启动包/同步初始化、首次子包跳转、WXML 渲染与图片、弱网往返和等待权威接口。应先用当前包哈希绑定的微信真机指标定位，再作单点优化。[^prd][^adr-runtime][^wx-start][^wx-render]

工程门禁与产品/平台门禁必须分开。本次研究的测试是本机合成负载；**未取得当前源码的 iOS/Android 真机流畅度证据、真实微信支付/退款/转账回调互通、正式 COS 权限验证或 UGC 平台安全互通**。`design:qa:status` 仍显示 `releaseReady=false`，因此不能据此宣布发布、PR 主干合并条件满足，或开启真实资金与公众内容。[^prd][^adr-gates]

## 架构与事实流

```text
微信原生页面（WXML/WXSS/TypeScript）
    │  HTTPS wx.request / 经配置的云 HTTP；会话、请求号、幂等键
    ▼
Fastify 模块化单体：身份 → 对象/行级服务校验 → 领域命令
    ├─ PostgreSQL：会员、护理、订单、账本、审核、审计的权威事实
    ├─ Outbox / 独立 worker：重试、补偿、扫描、回调消费
    ├─ 私有媒体网关 / COS：服务端签发、验证、派生与访问
    └─ 外部支付/微信安全接口：仅在各自正式门禁完成后接通
```

小程序不直接访问数据库。`services/http.ts` 将请求限定为 `wx.request` 或云 HTTP，统一 12 秒客户端超时；`services/api.ts` 对 GET 作按身份、源站、传输方式、权限模式的短时去重/缓存，并为写入带幂等键。服务端 `server.ts` 在全局前置钩子验证会员会话，业务服务再做 capability 与对象约束；`db.ts` 使用连接池、语句/锁/空闲事务超时及可重试事务。项目 ADR 明确不把 Medusa、Chatwoot、飞书或 AI 框架变成第二套权威库。[^adr-runtime][^adr-commerce][^adr-support]

这种结构的优势是订单、库存、佣金、购物权益、护理和审核能在同一 PostgreSQL 事务或追加式事实链中维护一致性；拆服务会把现已成立的事务约束变成跨服务补偿。外部接口应继续停在版本化 API/事件与 Outbox 边界。若未来容量证据证明单体独立扩缩容不够，再按冷热域拆读模型或 worker，不先复制业务事实。此为架构判断，不是性能实测结论。

### 数据访问与权限现状

| 入口 | 当前源码观察 | 风险与下一道验收 |
|---|---|---|
| 游客/会员 | 有受限公开读取；会员 API 校验签发会话及当前成员状态。`/v1/bootstrap/*` 有特殊处理，具体状态仍由领域服务核对 | 用无令牌、过期令牌、跨成员 ID、切换账号和重放矩阵覆盖 401/403/404 与脱敏；首页游客不得自动跳走。[^prd] |
| 移动管理 | `authority_grant` 按成员、capability、环境和有效期授权；管理服务调用 `AuthorityService.require*` | capability 只证明功能权限，仍须逐接口检查对象/行级范围、字段脱敏和审计；「创始人」不等于全量 PII。[^prd] |
| 旧 `/v1/admin/*` | 使用单一 `x-admin-token` 与由请求提供的 `x-principal-id`；服务再执行业务检查 | 这是较粗的内部边界。正式可达性、密钥保管/轮换、来源限制和审计主体不可只凭本地代码认定安全；优先迁移到受约束的人机身份/短期凭证，并证明旧路径关闭或隔离。 |
| PostgreSQL | 当前迁移中未见数据库级 `CREATE POLICY`/RLS 或应用/迁移角色分离；应用连接池直接读写业务表 | 应核查部署用户不是对象 owner/超级用户；评估只读、写入、迁移角色分离。RLS 是纵深防御候选，须在对象级策略和测试成熟后引入，不能替代服务校验。[^pg-priv][^pg-rls] |
| 媒体与渠道回调 | 预签发/令牌、私有读取、渠道签名/解密和 inbox 事实均由服务端处理 | 必须在真实 COS 桶/IAM、合法域名、真实微信签名/重试/密钥轮换环境验收；本机模拟不可外推。[^adr-gates] |

源码中已有请求体/超时边界、错误码、request ID、日志脱敏和 SQL/HTTP/池等待指标的基础，**但本轮未找到 API 或所附 Nginx 配置里的入口限流规则**；请求体限制与幂等不等于反刷限流。这是匿名身份、公开 Feed、上传和管理入口的待验收安全/容量缺口。不能只按 IP 盲加阈值：微信客户端及 NAT 可能共享出口，需按身份、接口风险、来源和实际峰值设计，配合可观测的 429/重试语义与压测，再在正确的公网入口实施。建议同时做接口清单的「主体 × 对象 × 字段 × 动作」矩阵和跨账户自动化，再评估数据库级角色与 RLS；不要为了追求架构层数先叠加 Redis、网关或另一套身份库。PostgreSQL 官方明确对象 owner 与普通 GRANT 权限不同，RLS 策略也不能简单等同于应用授权。[^pg-priv][^pg-rls]

当前 `lint:contracts` 检查到 219 个已注册 `/v1` 方法与 OpenAPI 对齐（文档共 221 个方法，另含 health），32 个类型化事件与目录对齐；这证明**契约形状**，不证明所有主体/对象组合都已做越权实测。隔离本地 API 对匿名 `/v1/capabilities` 返回 200，对 `/v1/me/authority` 和 `/v1/admin/runtime-metrics` 均返回 401；只能作为这三个入口的烟测。配置层禁止 staging/production 使用开发身份 adapter，并要求相应微信身份及密钥配置，但正式环境的凭据权限和网络隔离仍须单独审计。

### 最值得先测的流畅度路径

1. 游客冷启到「授权身份并开始」可交互；已登录热启到首页权威护理状态。按 `AppLaunch`、`FirstRender`、API 往返、首个可点击时刻分段。`App.onLaunch` 当前执行 `pruneUgcBackups()`，其中遍历草稿索引并作同步 storage 读写；多草稿时可能阻塞 JS 启动路径，**是源码推断，未见耗时数据**。官方建议减少启动阶段同步 API 与复杂计算。安全约束是遗留本地内容清理不能被悄悄取消。[^wx-inject]
2. 从首页到护理四步、提交感受、记录回看；观察连续 `setData` 的数据字节、渲染耗时、动画帧率、中断恢复、重复点击。页面已有本地状态锁与请求版本防旧响应，但渲染顺滑仍须测。微信建议避免滚动事件里的频繁 `setData`、控制 WXML 节点数和嵌套、优先平台动画。[^wx-render]
3. 社区首屏/长列表/头像与媒体；测图片下载、解码、列表内存、滑动掉帧和 WebView 回收。现有头像服务把受控小图写本地、列表可分页，不能据此证明所有图片/长列表都合理。官方提醒大图影响内存、解码与低端机滑动。[^wx-resource]
4. 商城直接结算与移动管理账目；量化子包首入、地址输入/键盘、弱网重试、订单与资金状态回看。33 个单页子包降低主包归属，但也让多个相邻页面首次跳转可能各自下载；先记录实际包下载与路由 P95，再决定按「购物」「管理」等访问簇重组或配置有限的 `preloadRule`。预下载会转移流量与内存，不能无差别全开。[^wx-preload]

网络瓶颈应分解为 DNS/TLS、微信客户端调度、API、数据库等待与响应体；不能把「接口快」等同于「页面快」。`RequestCoordinator` 当前对公开目录做 5 分钟 TTL、Feed 做 5 秒 TTL、bootstrap 做 1.5 秒 TTL，对资金/订单默认不缓存；此方向合理，但每个缓存必须维持身份与失效边界。客户端 12 秒超时保障可恢复性，不是 P95 目标。[^wx-network]

## Rust / WASM 是否值得引入

**当前决定：不引入 Rust，不改写 Node.js 后端，不把护理或结算规则迁入 WASM。** 理由是现有可量化热点主要是 SQL 聚合、池等待、包加载和视图渲染；资金链的大头是 I/O、外部渠道状态及数据库事务，改语言不会消除这些往返，反会增加构建、审计、跨语言状态与微信包体成本。历史社区热点用 SQL 索引与事务计数器解决，正是证据驱动而非语言替换的例子。Node.js 官方也建议先用分析器找 CPU 热点、避免阻塞事件循环；Worker 主要服务 CPU 密集计算而非 I/O 密集工作。[^capacity][^node-prof][^node-worker]

微信确实提供 `WXWebAssembly`（基础库 2.13.0 起；Worker 中从 2.15.0 起），但 `instantiate` 读的是**代码包内** `.wasm`/`.wasm.br` 路径，Worker 内文件放置另有限制；Worker 消息会复制数据。Rust 不是微信原生执行语言，Rust→WASM 还涉及工具链、包大小、JS↔WASM 数据拷贝及 iOS/Android 兼容验证。开源示例可用来做隔离 spike，不能视为生产依赖或性能证明。[^wx-wasm][^wx-worker][^rust-wasm]

只有出现以下全部证据才启动一个可回退 Rust/WASM spike：

- 同一个目标机型/版本/数据集的 Trace 证明**纯 CPU 算法**是核心交互 P95 的主要贡献者（例如稳定占该路径耗时 ≥30%，且 JS 优化、WXS/原生能力、后台异步都无解）；
- 算法输入输出小、与 `wx`/数据库/网络无耦合，结果可用属性测试与现有 TypeScript 实现逐字节对齐；
- A/B 在低端 Android 与 iOS、冷启/热启分别提升端到端 P95，且包含新增包下载/初始化成本；
- 不引入未经审核的加密/支付逻辑、私钥、个人数据跨边界复制或不可复现构建；失败可立即回退 TS 路径。

若未来服务端确有 CPU 密集媒体处理，先利用现有 `sharp`/异步 worker 隔离与 CPU profile；只有可复现的纯算法热点才评估 Rust 独立库或服务。上述 30% 是本研究的**spike 触发建议阈值**，不是 PRD 批准目标。

| P2 | `NFR-03` 外部压测、`pg_stat_statements` 和 EXPLAIN；按计划的数据分布复核索引、池预算、冷热缓存 | 延迟、错误率、数据库等待、IO/CPU、30% 容量余量；扩容/拆分/Rust 决策只根据实测。[^prd][^pg-stat] |
| P2 | `NFR-02` 可用性/故障注入与 `NFR-04` 备份恢复；值班、RPO/RTO 签字 | 演练与恢复数据集；没有真实值班与故障域能力不承诺 99.9% SLA。[^prd] |

本报告不是发布批准。当前工程继续以 PRD 稳定章节/验收 ID、当前包 SHA 和每个门禁的原始证据为准。
