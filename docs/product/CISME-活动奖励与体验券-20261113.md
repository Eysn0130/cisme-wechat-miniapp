# 活动旅行套装与收货体验券

本次用户明确要求新增活动奖励领取业务，依据《爱格荣活动奖励旅行中样领取MVP.docx》及三张商品/券素材。该增量启用专属活动兑换及体验券；不恢复旧任务投稿审核或自动发奖。既有十题护理档案、地址密文、支付回调、权限、积分和退款账务仍是对应权威。

## 业务边界与数据

- 活动兑换券：仅绑定已存在且有效的获奖会员；同一 canonical 会员ID在本权益全局仅一张券，重复获奖记录不再发第二张券；不可凭转发链接领取。每张券二选一、不扣积分、不计商品消费积分或佣金。
- 两个实物组合：净润洗发水100mL＋护发乳100mL；净屑洗发水50mL＋同款护发乳100mL。三个组件分账，共享护发乳库存；禁止挪用现有正装库存。
- 体验正装券：领取订单确认收货后自动发放，满198元减20元，自发放起30天；同一会员本权益只发一次，不叠加其他优惠券。适用商品由活动配置明确指定，发行时保存范围快照。积分可选；积分上限按券后商品金额计算，不抵运费。
- 尚缺品牌实际数据：三个组件真实库存与活动获奖会员名单；每人一张、发券后30天、大陆包邮、72小时发货及取消后原有效期不延长已由用户确认。后台必须明确配置并确认，未配置不可发布或发券。数据库初始零数为“未确认入库”，不冒充真实零库存。
- 正装券不是微信渠道优惠券：由商户结算价内扣减，微信收取最终现金；不改变现有渠道优惠组合安全约束。

## 页面与交互（HIGH；A–I、L–M、R 合并）

主要用户是已获奖会员，手机单手完成领取；次要用户是有现有商品、库存、会员或履约授权的运营。成功是领取一份正确组合并收到可核对订单；最严重错误是错给身份、重复扣券、共享库存超卖或展示虚假支付成功。

设计阅读：品牌会员的原生领取流程，延续低饱和紫色、真实产品图和纸券轮廓，重点是清楚选择及完成反馈。视觉辅助使用 design-taste-frontend，交互以 mobile-ui-ux-designer 和现有微信组件为准，不引入 Web 组件或动效依赖。

路径：我的 → 我的奖励；获奖链接 → 登录 → 绑定本人券 → 现有问卷 → 选择组合 → 地址与费用 → 确认领取 → 领取订单。已有有效完整档案不强迫重填，可主动修改。选择不替用户预先确认；推荐只显示在对应卡片，最终点选优先。

| 屏幕 | 主要层级（不超过7区） | 主操作/次操作 |
|---|---|---|
| 我的奖励 | 原生返回与标题；奖励/体验券分栏；券列表；领取订单；真实空/错态 | 立即领取；查看订单/去使用 |
| 领取 | 标题；两套真实产品图和规格；已选组合；地址；费用与时效；说明入口；底部确认 | 确认领取；修改问卷/地址/说明 |
| 领取订单 | 状态；组合快照；时间与物流；地址；费用；真实当前操作 | 确认收货；取消或售后 |
| 结算用券 | 原商品结算；一行优惠券；券列表底部弹层；价格分项；原提交 | 使用/不用优惠券；原积分可选 |
| 活动管理 | 活动配置；三组件库存；发放名单；券和订单状态；履约与导出 | 保存/发布/发券/发货；按状态核对 |

已有组件/令牌：care-onboarding、address-editor、pageRead、currentChromeStyle、shouldReduceMotion、action-main/action-text，颜色使用 --cisme-plum、--cisme-ink、--cisme-muted、--cisme-surface。只增加奖励券表现所需局部样式，不改 Tab Bar、会员卡或护理主流程。

320–374px 缩短图片高度、内容纵向滚动；375–430px 为基准；431px以上限制正文宽度。顶部让开原生胶囊，底部按钮留安全区。大字不截断金额或主按钮；弹层内容可滚动，关闭与当前操作固定。说明和长规则一触即达，规格、费用、期限、失效原因不可隐藏。

## 状态与操作契约（D、F、J、K 合并）

| 状态/触发 | 服务端与UI行为 | 失败及恢复 |
|---|---|---|
| 无券/未登录 | 空态或登录入口；不展示虚构资格 | 回社区/登录；链接不是凭证 |
| 券待使用→立即领取 | 本人资格校验；直接打开现有问卷或恢复已填档案 | 保留券和答案，显示重试 |
| 套装点选 | 明确勾选、短促按压；无库存不可选、不替换 | 两套均缺货保留券，提供客服 |
| 确认费用 | 服务端检查档案版本、地址版本、券、共享组件、规则快照 | 变更时重取报价，不自动提交 |
| 确认领取 | 持久化请求键；同事务锁券、组件库存与订单 | 超时保留同一请求键，查询原操作或重试 |
| 免费订单 | 创建即核销券和组件，进入待发货 | 不伪造微信支付事实 |
| 发货→收货 | 有履约权限者录入真实物流；本人确认收货后幂等发体验券 | 不凭动画、查物流结果推断收货 |
| 取消/撤销/售后 | 未发货免费领取可取消恢复；过期按活动规则处理；已发货走售后 | 不直接恢复已发货库存或新领取资格；无现金领取不产生退款款项 |
| 体验券使用 | 创建订单才锁券，支付成功核销，取消/超时释放 | 整单核验退款可恢复尚有效原券；部分退款不再次发券，不退券面值现金 |

券进入220ms轻移位与淡入；确认服务端成功后280ms收束为核销状态，随后单次细光掠过。等待时只显示加载，不提前显示“领取成功”。按钮按压120ms；无循环光效、无阻塞式开奖。减少动态效果时仅瞬时更新状态与文字。所有操作可不依赖动画完成。

点击区域至少44px，次要入口用文本，选择用勾选状态及文字，不仅依靠颜色。每个按钮有原生语义与名称；状态变更通过 aria-live 公告。动画与触控依据 [W3C 交互动画](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions) 和 [目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)，采用现有原生44px下限。微信在线文档本轮无法打开，具体API以已安装官方 DevTools 与本地小程序类型定义核验。

## 验收（N–Q 合并）

| ID | 可执行验收 |
|---|---|
| TRV-01 | 正确100＋100、50＋100两组合；共用护发乳并发不超卖；只剩一瓶时最多一单成功 |
| TRV-02 | 重复发放同获奖记录返回同券；跨会员或重放不同数据拒绝；每位会员全局一张 |
| TRV-03 | 恢复已有问卷；版本漂移必须重新确认；拒绝可选护理情况授权仍可选品；最终选择覆盖推荐 |
| TRV-04 | 地址/运费/时效/规则在提交前可见；订单保存组合及规则快照，不受后续编辑影响 |
| TRV-05 | 领取幂等、重试/断线/后台恢复、券锁定与组件占用/消费/释放一致；不扣积分 |
| TRV-06 | 旅行套装商品和运费均为零，无支付入口；正装券订单通过现有签名支付回调结算，不伪造收款 |
| TRV-07 | 权限核对、真实物流、收货一次发20元券；重复收货/另一奖励收货均不重发 |
| TRV-08 | 正装券归属/范围/门槛/到期/预占、积分可选、报价漂移、核验整单退款正确 |
| TRV-09 | 运营可配置/确认活动、库存、导入已有会员、发券/撤销、履约、分状态导出；普通会员无管理权限 |
| TRV-10 | 320/375/390/430px、加载/空/错/锁定/中断/减少动态效果的原生模拟器验证及源包哈希；真机尚无设备不得记为通过 |

无实际库存/获奖名单时完成开发、隔离测试和可审阅界面，活动保持草稿。用户已明确授权本轮新增业务与设计实施；真实发券、启用活动以核实配置为前提，任何真实扣款/退款仍不由开发验收代做。

历史事项：注销后仍通过既有隐私与数据权利申请处理领取资料及售后；已注销身份不能兑换新的套装或使用正装券。旅行套装售后关闭后，未使用正装券撤销；已锁定正装订单保留原约定价格，若再取消或整单退款则撤销该券，已支付不另追扣优惠金额。
