# CISME R0 PRD / 范围裁决增量

日期：2026-08-15  
基线：`CISME消费者小程序与AI经营平台_整合PRD_V2.1.md` V2.1-R4  
性质：纠偏增量，不替代基线 PRD，不扩大 R0

## 决策

当前交付名称固定为“本地可审核工程快照”，不是“R0 候选”“体验版候选”或“生产成品”。基础 share_id 的创建、访问与身份首触归因已补齐；只有交易 profile 及购买/退款归因、生产 RBAC/IdP、真实微信环境和设备证据完成，且 P0/P1 清零后，才允许升级名称。

| 裁决 | R0 能力 | 约束 |
|---|---|---|
| 保留 | 微信身份、护理周期、有效邀请→claim、私有真实上传、审核/补件/申诉、独立许可、品牌精选、简明积分账 | 所有状态以服务端/数据库为权威；开发适配器不得进入 preview/trial/release |
| 条件启用 | 积分发放、积分消费/抵扣、外部 UGC 公开、品牌内容、体验成员登记、选定交易 profile、自动 CI 预览 | 积分消费独立要求已实现的交易 profile、有效期内财务审批和 prepare/commit/release/refund-allocation 证据；其余分别要求财务、法务/内容安全、权属、审计、交易 ADR、凭据/IP 白名单证据 |
| 延期 | 评论、关注、个性化推荐、公开主页、复杂成长、公开任务广场、购物车/券、纯积分实物、消费端 AI | 不得因视觉原型存在而进入 R0 成功口径 |
| 舍弃/隐藏 | 无 handler 的搜索/筛选/标签、静态资格徽章、假订单/支付/上传/积分/QA 控件 | 没有真实动作和失败态就不呈现为可操作控件 |

## 本轮独立裁决与实现修正

1. **身份主键**：微信身份按 `(app_id, openid)` 唯一；一个会员可关联多个受控微信身份。禁止全局 OpenID 或一会员一身份假设。受控 UnionID 合并/人工 merge 仍未实现，不计入完成。
2. **用途许可**：`content_storage`、`human_review` 是完成投稿审核所需用途；`feed_readonly` 是独立、默认关闭、可撤回的公开展示用途。基础任务奖励不得以品牌转载/广告许可为条件。
3. **草稿**：界面只有在 `PUT /v1/submissions/{id}/draft` 成功并返回新版本后才能声称已保存；版本冲突和离开前保存失败必须可见。
4. **证据替换**：旧媒体保持 current，直到新媒体上传、校验和数据库事务切换全部成功。对象删除通过 durable cleanup queue 异步完成；不得先删旧对象。
5. **奖励 claim**：领取后的 submission 创建 pending reward claim；只有审核通过且签字规则在命令发生时仍有效才批准并生成积分资产。所有任务、投稿、积分和审核读模型也按当前时钟重新计算规则有效性，长运行进程跨过审批到期后不得继续宣称积分启用。本地已实现财务操作员发起、不同财务复核员批准的整 lot 解冻、到期、剩余余额冲正，以及拒绝后升版重提；四桶守恒、流水、事件和审计在同一事务。错误转账追回、已消费欠分/还款和生产对账仍未闭环，积分默认关闭。
6. **公开内容**：领奖审核与公开发布继续分离；可选许可撤回只停止新增展示使用，不得冻结既有基础奖励或改写历史审核证据。
7. **护理暂停与聚合版本**：activate/pause/resume/terminate/milestone 必须带版本和幂等键；phase 动作还必须带原因码。并发同键请求在加锁后复查幂等记录，每个 D1/D7/D14/D28 护理事实都推进 care aggregate version，陈旧 `expectedVersion` 不得越过新里程碑。只有已签策略内原因可暂停，开放暂停事实记录本地日历天数，恢复时只顺延未来里程碑，超过上限转支持处理。设备弹层/返回仍按视觉交互门禁验收。
8. **交易与归因**：商品仅为权威只读目录。基础 `share_id`、匿名访问事实、登录后的首触身份归因与防自归因已实现；MAKE 是唯一规划方向但 runtime 仍 UNSET，订单/支付/退款/物流/对账及购买/退款归因仍不存在，因此复购北极星尚不可实测。积分消费保持独立关闭，不阻断现金交易方案的评估和实现。
9. **后台治理**：邀请 campaign 不再通过手改 seed 运营；本地提供只读列表和 review-lead-only 的版本化、幂等、证据化、审计更新，且容量不能低于现有有效分配。共享 admin token 仍只适合本地评审；生产必须接企业 IdP/MFA、角色所有者、高风险 maker-checker 和审计查询。
10. **Worker 交付事实**：支持的 publication 事件只能记录 `applied` 或因许可撤回而安全 `suppressed`；来源不存在/状态无效/SQL 错误必须重试并进入 DLQ，不得写 `processed_at` 冒充落地。未实现 handler 的事件通过 backlog API 可见但不消费；生产 SLO/告警/其余 sink 仍是发布阻断。
11. **原生表现层**：继续使用原生 WXML/WXSS/TypeScript；动态窗口/胶囊几何、页面级样式、CISME tokens 与真实图标资产是约束，不迁移 Taro/uni-app。加载/错误时不得显示虚构权威数字，Profile/Post/Submit 的异步响应必须按 attempt/page 生命周期丢弃迟到结果。

## R0 接受口径

本地工程可接受的纵切是：开发身份或未来真实微信身份 → 合法资格 → planned/active 护理 → D7 有效邀请 → 原子 claim → 真实对象上传 → 服务端草稿 → 私有审核/补件/申诉 → 条件 reward claim/积分账。任何 URL/localStorage fixture、静态截图、假上传、假支付或单页 happy path 都不构成闭环。

## 仍阻断候选签字

- 交易 profile、购买/退款归因与复购事实。
- 积分错误转账追回、已消费欠分/还款、生产对账及企业角色所有权（基础 maker-checker 已本地实现）。
- 生产后台 IdP/MFA/RBAC。
- 已配置 AppID 值的归属/项目角色证明、AppSecret、合法域名、公网测试 API/DB/对象存储、隐私与法务文本。
- 微信开发者工具同状态视觉回归、iOS/Android 真机、弱网/键盘/拒权/断传证据。
- Git remote、受保护分支和可核验 CI run；当前不能用 YAML 文件冒充 CI 执行。
