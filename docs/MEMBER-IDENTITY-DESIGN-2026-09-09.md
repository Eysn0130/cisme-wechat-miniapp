## 业务结论

勾选用户协议后，可以开始微信登录并识别会员账号；不能把这一勾选解释为已经取得头像、昵称、手机号或社区公开展示授权。产品采用简化流程：阅读协议 → 点击“登录” → 自动识别账号并进入目标页面，已有资料在后台同步。首次选择头像、填写昵称及按需绑定联系电话，仅在设置页由本人操作，不拦截登录。已有会员登录不覆盖其保存的昵称。

头像昵称是用户可修改的会员资料，微信身份标识用于识别账号，联系电话用于联系与核验，三者分别处理。手机号不作为展示名称，不因相同手机号自动合并会员，不向社区接口返回。

## 身份及资料生命周期

1. 登录只建立或恢复微信身份对应的会员，不把登录回调的名字写回已有资料。
2. 用户选择头像后，原生 Canvas 先裁切转换；服务端再次解码、裁切为 128 像素 JPEG 并重编码，移除原图元数据。拒绝外部图片 URL、临时路径、SVG、异常图片与超限内容。
3. 昵称、头像与资料版本在数据库事务内保存。旧页面提交旧版本得到冲突响应，防止覆盖较新的修改。
4. 保存立即用于本人“我的”和“护理”展示。跨页使用同一会话内的资料快照，并拒绝旧请求倒退覆盖新昵称。
5. 社区展示默认关闭。主动开启后待审核；修改公开头像或昵称需重新审核。关闭后，后续社区读取立即使用默认身份。无法保证删除别人已保存的截图或外部副本，协议如实说明。
6. 退出或切换账号时清理资料快照与头像缓存，处理仍在进行的图片写入，避免串号。头像本地缓存限制数量并清理旧文件。

原始护理、投稿图片沿用 COS 流程；小尺寸会员头像作为会员资料存入上海数据库，便于和资料版本原子更新。二者用途、存储与生命周期不同。

## 联系电话

联系电话由微信独立授权按钮发起，再由服务端兑换短期凭证。保存加密号码及匹配摘要，客户端仅收到脱敏号码。授权凭证有重复使用校验，绑定与解绑按会员串行处理。

已有号码可解绑；解绑删除联系方式中的加密号码和匹配摘要，保留必要操作与凭证使用审计。平台获取手机号能力尚未完成配置时，界面如实显示不可用，不能把接口开发完成当作平台能力已开通。当前仍未声称完成真实手机号绑定。

## 数据与接口

- 增量迁移：`202609090006_member_identity_display.sql`，新增头像、资料版本、完成时间及社区审核字段。回滚在已有资料时拒绝直接丢弃数据。
- 本人资料：现有 `/v1/me` 与会员资料接口扩展；本人响应带头像、版本和脱敏电话。
- 团队公开资料审核：`GET /v1/team/member-profiles`、`POST /v1/team/member-profiles/:memberId/review`，会话及团队权限双重校验。
- 联系电话解绑：`DELETE /v1/me/phone`，仅操作当前会员。
- 社区作者统一采用服务端白名单投影；默认私有、会员非活跃、未审核或审核被撤回时不输出其资料。
- 审计记录动作和审核原因，不把原始联系电话写入这些操作日志。

- 微信开放文档部分页面本次无法读取，因此未引用无法核实的段落；第三方 SuperApp 的相似 API 不作为微信小程序能力证据。
