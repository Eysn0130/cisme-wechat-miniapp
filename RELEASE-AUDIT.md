## CI/tooling decision

- Official pages were rechecked on 2026-08-15; the two packages remain separate in purpose.
- Official `miniprogram-ci` is suitable for protected compile/preview/upload automation only after upload key, fixed/allowlisted IP, AppID/project permissions and manual approval are present: <https://developers.weixin.qq.com/miniprogram/dev/devtools/ci.html>.
- `miniprogram-mp-ci` is a project-member management capability, not the release pipeline: <https://developers.weixin.qq.com/miniprogram/dev/devtools/miniprogram-mp-ci.html>.
- The isolated `tools/wechat-ci` audit currently reports 73 advisories (41 critical, 16 high, 15 moderate, 1 low); automated use remains opt-in and risk-gated. The signed local WeChat DevTools CLI is the preferred first credentialed path.
- The repository workflow currently expresses only a protected-preview design; required reviewers, fixed runner egress IP and the WeChat IP allowlist are external settings and are not proven by YAML. The current isolated script performs `packNpm + preview`, not upload.
- Ordinary push/PR CI runs non-strict `design:qa:status`: it validates manifest/package structure but may be green while `releaseReady:false`; it is not a candidate-acceptance gate. A manual workflow dispatch or `candidate-*` tag adds a non-credentialed strict `candidate-design-qa` job after `verify`. The credentialed preview job and isolated CI entrypoint also run strict Design QA plus AppID, public-origin, legal/domain/manual and risk checks before loading preview tooling, so they cannot create a QR while route/device evidence or P0/P1 closure is missing.
- The evidence index is schema v2: every referenced file is verified by SHA-256, byte size, MIME, real PNG/JPEG structure, dimensions, kind, source hash and route/state metadata; unreferenced index entries and duplicate reuse are rejected. Route acceptance requires separate reference/native/comparison artifacts for each applicable state, real-device evidence requires hardware metadata, package-budget errors feed the strict result, and the credentialed preview job depends on the complete `verify` job.
- There is no Git remote or verifiable CI run. Workflow YAML is not execution evidence.

## Sign-off condition

Do not call this a delivery candidate until P0/P1 are zero, the core flow has no dead end, same-state visual/interaction acceptance passes, DevTools has zero project console/network errors, iOS/Android evidence is attached, and the artifact is bound to a commit/AppID/version/hash.
